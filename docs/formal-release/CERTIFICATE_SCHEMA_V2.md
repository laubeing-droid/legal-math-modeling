# FormalReleaseCertificate Schema v2 (M10)

Status: schema artifact of the 2026-08-15 theory-absorption construction.
The certificate is generated by GitHub Actions as a run artifact; it is
never self-signed locally, and a local copy without CI run identity is
not release evidence.

## Binding (required fields)

| Field | Source |
|---|---|
| subject commit / tree / dirty | `git rev-parse` at CI checkout |
| OS / arch / runner image | GitHub runner environment |
| Lean / Elan / Lake toolchain | `lean-toolchain` pin |
| Mathlib / dependencies | `lake-manifest.json` digest |
| source hashes + theorem inventory | `scripts/generate_formal_release_certificate.py` |
| clean build result | `lake clean && lake build` log in CI |
| guard scan | `scripts/scan_lean_guards.py` in CI |
| axiom audit | `lake env lean JurisLean/AxiomAudit.lean` raw output |
| Python collection + full tests | pytest manifest + full log |
| mutation / refinement reports | controlled checker-input `mutation-property-report.json`, runtime-refinement-report.json |
| limitations + certificate digest | embedded in the certificate |
| run identity | `scripts/ci/build_run_identity.py` (`ci-run-identity.json`) |

## Gate rule

Release PASS requires, for the SAME subject SHA/tree: CI clean build, full
tests, guard, axiom audit, manifest parity, mutation suite, refinement, and
independent verifier all green, with downloadable artifacts whose digests
match the run identity. Any UNKNOWN / TIMEOUT / SKIP / NOT_RUN /
BACKEND_UNAVAILABLE / ERROR / CI_NOT_RUN blocks release. No push, tag, or
release happens without per-round user authorization.

The mutation report covers controlled malformed inputs against the certificate,
receipt, source, temporal, proposal, and translation checkers. It does not claim
Lean-source or Python-implementation mutation coverage.

## Claim boundary

Allowed after a green release certificate:

- The Lean modules listed in the inventory built without errors on the
  subject commit, and the named theorems type-check under the pinned
  toolchain.
- The Python contract suites passed on the subject commit.
- Certificates/receipts are content-bound to the listed digests.

Never allowed (with or without a release certificate):

- "The entire juris-calculus is formally verified by Lean."
- "Checker acceptance means legal correctness or full runtime proof."
- "The Python implementation is fully refinement-proved by Lean."
- Any claim beyond the bound commits, fixtures, and evidence domains.

## Evidence domains in the certificate

LeanProofReceipt, FiniteModelCheckReceipt, SolverWitnessReceipt,
TranslationReceipt, RuntimeRefinementReceipt, HumanLegalReviewReceipt. The
overall certificate status never exceeds its weakest bound domain, and each
domain keeps its own subject, issuer, and checker.
