## Unit, date and legal-cap boundary

The common `AmountTag` (currency/unit/version) in the real closed-account theorem is an explicit same-unit premise; it is not a currency-conversion rule. A common valuation time is the fixed input context specified by the original question. `factDate` records the actual payment date and is not silently used as valuation time. `fromQPayload` takes that actual `p.factDate`; for arbitrary Q ledger events `fromQCash` takes an externally supplied `dateOf`, whose correctness is not derived by the arithmetic adequacy theorem. The Q→R relation preserves values and fields only; it does not establish cross-currency or cross-time valuation.

The frozen question states any cap as an externally supplied abstract predicate. This package does not impose a cap on cash amounts or reconstruct a statute from a payment identifier. If an external legal input supplies a cap, its target must be the legally specified proceeds object; it is not presumed to equal gross cash, net cash or each label sum. The evaluation time must be supplied by that legal input, and additivity does not follow automatically. If the legal source, capped object, time or composition bridge is missing, the cap inference remains `UNKNOWN`. The cash invariants neither prove a cap nor add a legal duty.
