## Frozen-clause mapping

Success and failure branch costs are already included in their corresponding branch net amounts; the common cost is subtracted once. When that common term is instantiated as `k = -netCash common party`, it is a nonnegative cost only if the common net cash is nonpositive.
- **L99 — finite counterexamples.** With zero failure cash and no common cost, probability `9/10` with success cash `1` has expected cash `9/10`, while probability `1/2` with success cash `4` has expected cash `2`; higher success probability alone does not order expected cash. Under the same fair Bernoulli law, a sure cash outcome of `5` and a `10/0` lottery both have expected cash `5`. At wealth `0`, both outcomes of the lottery are in `Ici 0`; strict concavity of `sqrt` gives lower expected utility for the lottery than for sure cash `5`.
- **L101 — restricted utility and threshold comparison.** `bernoulli_utility_two_branch` adds cash through an explicit wealth input and noncash outcomes through an explicit utility-valued mapping. `linear_risk_neutral_expected_utility` and `linear_risk_neutral_action_order_iff` require a shared positive slope for the ordering result, fixed common wealth/offset/noncash consequence, and allow the two actions to have different probabilities. The threshold instance is only the zero-cash baseline versus success cash `b > 0`, failure cash `0`, and common cost `k`: the existing `u06_4_threshold_increasing` gives `k/b ≤ q`. The nonlinear square-root example shows why the ordering claim is restricted to linear risk-neutral utility.
