## 提示词正文（从此处复制）

你的任务分四个角度，每个角度都要独立成立又相互咬合。总目标是把"法律统一数学模型"从口号推进为可施工的数学理论与工程方案。你能访问 GitHub 公开仓库 `github.com/laubeing-droid/legal-math-modeling`（基线提交 `b00d315`，CI run 35833467010 全管线绿，含 release-certificate 与 final-gate），并能联网检索论文与其他 GitHub 项目。

【证据规则（先于一切任务）】随附锚点清单与远端仓库是你唯一允许引用的既成事实来源；需新证据处标[需补充证据]；文献检索产出的引用必须给可点开链接（DOI/arXiv/官网），找不到就写 NOT-FOUND，禁止编造条目；你自己知识里的内容必须标"未核验知识"。仓库里没有的定理不许当作已有依赖。

【角度一：统一数学理论】
以数学自身的标准，而不是工程可用性的标准，审查并完善"法律地位构成理论"：
- 统一对象：裁判 (N 规范系统, F 事实与证据准入, E 论证态势, P 程序状态, t 时点, q 主张) → Status ∈ {主张成立, 主张不成立, 程序性处置, 未决}；核心命题"法律地位的产生来源是封闭的"。
- 你要回答的数学问题：这套理论的原始对象与公理该怎样选择，使十三维（概念/推理/理解/适用/程序/规范模态/事实与证明/责任与后果/冲突与位阶/时间/量化计算/效力与溯源/主体与关系）成为同一结构的投影而不是十三个拼盘？给出至少一种候选的统一数学基座（例如：带优先级的道义逻辑+序上的不动点理论；或依赖类型论中的商结构；或 Galois 连接对偶下的规范-事实对偶），说明各维在该基座上的像、以及哪个维在该基座上失真。
- 与既有数学的关系（必须查论文）：道义逻辑（norm positions、可废止道义逻辑）、论证理论（Dung 语义、ASPIC+、value-based AF）、证明责任的概率/贝叶斯模型、法律知识表示（LegalRuleML、LKIF）、时序法律逻辑。逐项说明我们复用什么、绕开什么、自建什么，给链接。
- 必须查 GitHub（给仓库链接+星数+最近提交时间）：Lean4/Isabelle 上的道义逻辑或法律形式化库、论证框架的可执行实现、LegalRuleML 工具链。评估哪些可以直接借壳，哪些必须自写。
- 产出：数学基座选型报告（至少两个候选的对比表+推荐+失真清单）。

【角度四：蒸馏管线资产的数学消化】
背景事实（2026-09-23 修正计数）：用户的法律蒸馏管线已产出 80,430 条带原文引文锚点的中文蒸馏记录——wave1 方法库 40,428 条（78 源）+ wave2 11,405 条（94 组）+ wave3/4 28,597 条（wave4 覆盖 133 册书、45.7M 字符源文）。记录体例含"案情—裁判要旨—争议焦点—分析—关联法条"结构化字段与行号锚点。
- 设计"记录→形式化候选"的消化协议：从蒸馏记录中自动/半自动提取规则候选（法条引用、要件枚举、证明责任分配、期限规则、赔偿公式）的流水线各阶段定义、每阶段的验收断言、人工闸门放哪、如何防止把书证断言当成已证事实（提示：它们只是候选，须回查原文与法条，fail-closed）。
- 该协议与角度一的数学基座如何对接：记录提取出的规则候选落到哪个类型族、由哪条定理保证其进入推理时不携带未核验断言。
- 必须查 GitHub 与论文：语料→规则/本体提取的既有管线（法律信息抽取、LegalRuleML 生成、LLM+形式方法混合管线），给链接，说明复用与自建边界。

【硬性检索义务】四个角度合计：论文检索不少于 12 条有效引用（含随附 8 条文献锚点之外的新发现至少 4 条）、GitHub 项目不少于 6 个（给链接与活跃度）。每条注明用于哪个角度。检索不到的部分明说 NOT-FOUND，不许用"众所周知"顶替。
