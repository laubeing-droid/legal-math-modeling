# A　法律统一的数学基座：从“结果封装”改为“法律关系的构成与变动”

## A0. 裁决

**现有ULM主干不能作为法律已经统一的证据。** 它有真实的通用推理、数值计算及工程安全成果，但关键法律意义仍留在输入的`finding`、`succeeds`、`allows`、`gamma`或字符串见证中。把这些结果放进同一类型，不等于解释这些结果为什么依法产生。

本报告推荐的研究对象改为：**在给定法域和解释语境中，法律地位如何由规范、事实、证据与制度性行为共同构成，怎样变更和消灭，以及在何种程序与证明条件下可以作出具有何种效力的判断。** “主张成立／不成立／程序处置／未决”是这个结构上的查询，不是整个法律世界的本体。

这是一份新的候选理论与施工设计，尚不是已经在仓库证明完毕的理论。以下不把新提出的语义、定理目标和待实施算法写成既有成果。

## A1. 为什么原对象需要修改

原提示词的函数`(N,F,E,P,t,q) → Status`可以作为输出接口，却不足以定义法律。它没有直接解释权利义务的主体和对象、权能与许可、责任和救济、关系变动与裁判效力。把合同、侵权、刑事责任和程序性请求最终都压成“成立”，丢失的恰好是需要统一的法律内容。

十三维也不属于同一种数学对象：“主体与关系”“时间”“规范模态”主要是对象或属性；“理解”“推理”“适用”主要是操作与判断活动。不能直接把它们理解成十三个独立坐标。这里保留十三维作为覆盖要求，但将“投影”精确化为**同一法律语义结构上的有类型视图、查询或变换**。并非每个视图都可逆，也不是每个视图都能单独恢复裁判。

上传书证将“主体与关系”对应`LegalIds/ContextKey/TrustVector`，将“效力与溯源”对应subject绑定。这些只是可能承载标识的工程对象，不能直接算作霍菲尔德关系或法律效力的实现。法学概念需要在语义中有自己的判准。[书证：wave4-evidence.md，维度12—13；源码：ULM01、ULM14、ReceiptAuthority]

## A2. 三个候选的比较

| 候选 | 共同数学对象 | 优点 | 必然补入／失真风险 | 结论 |
|---|---|---|---|---|
| ① 纯可废止道义逻辑＋有限不动点 | 条件规范及其可废止后承 | 适合义务、禁令、许可、例外和部分违反后果，能复用现有Horn与论证计算 | 仅凭这些不能充分表达权能实施造成法律关系改变；证据标准、身份构成、程序效力不能只当普通事实；整体非单调更新不能套单调不动点 | 保留为子理论，不作唯一总基座 |
| ② 语境索引的法律关系／制度性变动语义＋结构化可废止推导 | **有方向的法律地位、产生或改变它们的规范操作，以及带法律理由的推导关系** | 静态地位与动态变动互相定义；能把证据、程序、时间和救济落实到同一法律推导，而非接线 | 必须具体给出构成规则、效力条件、证据责任与冲突语义；不能把未完成部分再藏进`gamma` | **推荐** |
| ③ 依赖类型／证明项及商结构 | 有类型证明项与等价关系 | 适合编码同主体、同请求、单位与来源等约束；能证明重命名和转换保持 | 若法律内容只剩字符串和外给谓词，会重演当前问题；商掉太多内容还会把法律差异抹平 | 作为②的形式化语言和实现技术，不代替②的法律语义 |

## A3. 推荐基座的原始对象

### A3.1 法律签名，不以字符串拼接充当法律本体

设`Σ`是一份多类法律签名。至少包含主体、角色、客体、行为、事件、法律关系实例、命题、规则、法源、机构和时间。主体身份与诉讼角色必须分开；同一个自然人可以在不同关系中承担不同角色。

法律关系实例不是`claim_id`。例如一个给付关系至少绑定：权利人、义务人、给付内容、标的或金额、产生根据、适用时段和该关系的状态。金额和日期必须绑定回这一个关系，不能只在案件级数组中保留数字。

语境`κ`包含法域、规范版本与相关时间、事项、程序阶段、解释分支及必要的主体范围。语境不是任意增加二十个metadata字段；只有会改变规范适用、证明条件或法律效果的内容才进入法律语境。运行编号与哈希仍保留，但位于工程证据层。

### A3.2 静态地位与动态权能

同一项定向给付关系可以从两端观察：

\[
\operatorname{ClaimRight}_{\kappa,t}(a,b,\varphi)
\iff
\operatorname{Duty}_{\kappa,t}(b,a,\varphi).
\]

这里两侧不是两个互不相关的布尔值，而是**同一个关系实例的两种观察**。同理，区分自由与无请求权、权能与受变动地位、豁免与无权能。霍菲尔德语境中的`liability`是受他人法律权能影响的地位，不能误译为损害赔偿责任。[R02、R03；书证“季955–57”]

但不能反过来把所有法律内容强塞进八个词：身份、登记状态、组织关系、物权的对世结构、多方关系以及公法职权需要相应构成结构。公权力施加刑罚的关系也不能伪装成普通债权人向债务人索赔。

**法律上的权能不等于行为被许可。** 某种行为可能违反内部限制，却依适用规范对外产生效果；是否产生效果与是否承担责任必须分别推导。统一模型应能表达这种组合，而不是规定`Forbidden(action) → NoLegalEffect(action)`。[R02、R03；《民法典》第61条可作为后续具体规则族的检验材料]

### A3.3 统一判断语言

采用有类型的判断，而不是将每一类内容做成孤立服务。基本判断形状包括：

```text
Occurs(event, actor, object, time)
QualifiedAs(factualPattern, legalConcept, context)
Applicable(norm, relation, context, time)
Holds(position, relation, time)
Competent(actor, legalOperation, affectedRelation, context)
Established(proposition, issue, evidenceBasis, proofPolicy, proceduralStage)
BurdenOf(party, issue, burdenKind, stage)
LegalEffect(event, operation, affectedRelation, effectiveTime)
Binding(decision, partiesOrScope, issue, time)
```

`Established`不是历史世界“真的发生了”，`Applicable`不是法条文本“存在”，`Competent`不是软件用户“有管理员权限”，`Binding`不是任意人写入一个`reviewer`字符串。

规范统一写成可检查的、具名的规则：变量与类型、前件、结论或法律变动、法源依据、适用条件、例外及其作用位置、严格／可废止属性、时间范围和优先依据。法律解释争议保留为不同的规则候选或解释分支，不能用一个无说明的`policy.succeeds`吞掉。

### A3.4 统一推导与变动

令`Tκ`为在语境内被采用的、来源明确的规则集合，`B`为准入的证据与基础判断。用

\[
T_\kappa;B\vdash j
\]

表示按规定推导规则构造出的判断。基本推导只能从准入基础、实际规则实例及其已证明前件构造。不得直接把本次请求的目标结论放进“已审查”字段，再证明字段被忠实转发。

对可废止规则，先构造包含实际前提与实际规则的论证，再由**独立给定的法律冲突语义**产生攻击，并由有来源的优先规则生成击败。不能只有同请求与非空字符串就叫合法攻击。接受语义产生一个或多个可接受解释分支，不预设始终只有一个实体答案。[R04、R05]

制度性行为的语义是对法律关系结构的变换：

\[
X \xrightarrow[\kappa]{e,r} X'
\]

它要求实际事件`e`满足规则`r`规定的法律效果条件。前后结构的差异必须来自该事件及相应构成／变动规则。记录更新、用户点击按钮、程序从`heard`转`decided`本身没有这种法律效果；法院裁判、当事人有效意思表示、依法登记等行为是否以及怎样发生效果，则由各自规范生成。[R02、R03]

法定时间届满与事实行为也可能依规范引起变化，并不都要求某个主体行使权能。因此变动分为**法律行为／制度性行为触发、法律事实触发、证据与认识状态更新**，不能用一个“必须有人授权”的条件统一抹平。

## A4. 这为什么不是换名字的工程拼装

统一性不能由前述术语表自证，必须由以下相互制约的法律定律检验。

| 法律统一要求 | 应证明的东西 | 能识别什么假统一 |
|---|---|---|
| 关系对应 | 一项给付关系两端的权利与义务在主体、内容、时点上对应 | 分别填了两个“成立”而内容和主体不一致 |
| 规范实例与行为对应 | 到期未履行、瑕疵履行、预期违约各按其构成条件产生相应评价 | 任一核验事实都可以触发“违反” |
| 法律变动有根据 | 关系增删改可追溯到实际事件和适用的变动规则 | 仅仅改stage就声称解除合同；或反过来禁止所有程序事件改变关系 |
| 证明责任与后果耦合 | 对指定争点、指定负担主体与程序阶段，证据评价依法进入特定后果 | 数字概率、证据计数或外给finding直接替代法律认定 |
| 救济与关系绑定 | 救济对应实际受侵害关系、责任类型、选择权主体、范围与竞合规则 | 同一个normId就能配任意赔偿或救济 |
| 时间与地位一致 | 同一法律事件、适用版本、截止点和变动生效时点共同约束结论 | 日期只是显示信息；法律版本更新后旧结论无条件保留 |
| 规范冲突与价值保持差异 | 排除、协调、优先、不可比具有明确不同语义 | 把所有冲突交给一个数字排名或任意Bool |
| 法律同一性 | 对仅重命名主体的变换保持法律结果；对改变主体角色、否定、比较符或时间的变换能够改变结果 | 哈希不变被误认为法律相同，或数字多重集保留被误认为关系保留 |

需要形式化的是这些法律命题，以及它们在具体规则族中的共同实例化。它们才是模型的承重结果，播报安全定理退居附属保证。

## A5. 十三维如何成为同一结构的视图

| 维度 | 在共同语义中的视图／操作 | 不能用什么替代 |
|---|---|---|
| 概念 | `QualifiedAs`及其构成规则、语境化类型约束 | 只有概念ID和标签 |
| 推理 | 同一规则语言上的严格／可废止证明树及攻击位置 | 只把多个求解器串联 |
| 理解 | 源文到规则解释的候选关系、可争议解释分支及采纳理由 | NLP相似度即法律意义 |
| 适用 | 对规则变量的合法代入，前件、范围、例外、时点共同决定适用 | 布尔`active` |
| 程序 | 程序行为、判断就绪条件、认定或裁判的拘束范围 | 阶段枚举、程序事件永不改变实体 |
| 规范模态 | 对行为的规范评价与对关系的构成操作；明确区分许可和权能 | 模态枚举互异即模态理论完整 |
| 事实与证明 | 事实命题、证据支持与反驳、责任、标准和认定效力 | 有证据即满足、概率即裁判 |
| 责任与后果 | 违反、归责、因果、抗辩、责任类型与救济的推导 | `normId`相同即有效救济 |
| 冲突与位阶 | 同一规则与论证之间具理由的优先、协调或不可比关系 | 工程receiptRank或者全球权利总分 |
| 时间 | 法律事件时间、适用时段、期间运算与变动生效时间 | `factTime < procedureTime` |
| 量化计算 | 已确定请求基础下的金额、分配、上限、抵扣、利息及舍入 | 单位一致或eval=denote即法定金额正确 |
| 效力与溯源 | 规范承认、适用效力、个案拘束范围与规则解释来源 | 签名、subject和hash本身 |
| 主体与关系 | 同一关系的主体方向、角色、客体、第三人效力及权能结构 | CaseScope、用户角色和TrustVector |

视图不等于十三个独立求解器。比如“期限届满”在时间视图中是运算结果，在权利视图中可能只是抗辩发生，在程序视图中可能要求当事人提出，三者来自**同一个期限规则实例**，不能在三个模块各写一遍相互无关的法律判断。

## A6. 一个必须贯穿数学、JC与Harness的法律测试族

以下是条文结构测试，不是对任何真实案件作出的法律意见。

### A6.1 全面按约履行与违约

当前`DDLDefinitions.directViolation`不读取`actor`、`action`或事实`predicate`。活动义务加同slice核验事实即成立。因此把事实内容改为“已经全面按约履行”，形式上依然能构造“直接违反”。这是法律条件缺失，不是播报格式问题。[源码：DDLDefinitions.lean]

新的规范实例必须把履行内容、对应主体、期限与违反类型联系起来。届期不履行只是其中一种；预期违约和瑕疵履行各自有条件，不能用“现在没找到履行证据”统一替代。履行后的现存义务和履行前是否发生过违约也应分别记录。第577条对违反义务内容的要求，是这个测试的实体依据。

### A6.2 诉讼时效与权利存续

第192、193条表达的规则不是“时间到了→实体债权消灭”。抗辩、不得主动适用、同意履行和自愿履行的效果需要分别表达。第199条规定的特定权利存续期间届满则有不同结构。因此统一的不是一个名为`expired`的状态，而是**时间事实依不同期限规范作用于不同法律地位**。

### A6.3 制度性决定与实体关系改变

第580条第二款规定一定条件下法院或仲裁机构可依请求终止合同权利义务关系，同时不影响违约责任承担。模型必须能表达：特定关系终止，但另一类责任关系不因此消失。

原`applyProcedureCause`只更新stage并保留`normativeMarker`，可证明这一个函数不改标记；它不能推导所有程序与制度行为均不改变实体法律关系。正确目标是“**无法律效果根据的机器状态转换不得制造法律变动**”，而不是“程序绝不影响实体”。

上述条文可在[最高人民法院文本](https://www.court.gov.cn/zixun/xiangqing/233181.html)逐条核对。本测试族分别检验概念、主体、模态、事实与证明、适用、程序、时间、后果、效力和计算的共同作用；只给四个输出状态仍然不能通过。

## A7. 五座桥必须先纠正法律命题

| 原桥名 | 不可直接接受的隐含命题 | 改成的实质任务 |
|---|---|---|
| 违反→攻击 | 违约自然击败原义务 | 先构造违反／归责／救济的法律推导；只有法律规定为反驳、阻却或减免的内容才进入相应攻击位置 |
| 例外→undercut | 所有例外均只攻击推理规则 | 区分否认事实、否认要件、阻却适用、免责、减责、行使抗辩、程序障碍；再映射到其准确对象 |
| 优先级→击败政策 | 有一份排序表即完成法律冲突解决 | 从适用的位阶、特别规则、时间规则或个案价值理由生成可验证优先／协调关系 |
| 证明责任→裁判闸门 | 外部填`satisfied`便等于证明标准满足 | 对争点、负担主体、证据结构、标准和阶段给出推导；同时保留求解未完备与依法证据不足的不同后果 |
| 时间→适用性闸门 | 一个时间比较式涵盖时效、除斥、溯及与程序期限 | 分别建模期间计算、法律效果和过渡适用，并绑定同一法律关系与事件 |

## A8. 原始假设、数学证明与法律核验的边界

可以作为数学前提的，是公开列出的签名、规则语法、具体编码、有限性、单调子算子及所选择语义的条件。可以作为案件条件输入的，是指向特定来源并经过相应准入的事实或假设。两者都不得化装成“请求结论已经正确”。

应分别证明：语法良构；推导相对于独立语义的可靠性；所声明片段内的完备性；法律关系视图的一致性；法律变动规则的前后状态性质；实现对上述语义的精化。自然语言法条与其编码的对应、证据是否真实、个案是否应采用某一解释属于另行法律／经验核验，不是通过更换构造子名称就能证明。

“法律地位来源封闭”只能先提出一个**相对于规则承认制度、已建模权能和解释语境的生成性命题**：每一被系统正式主张的地位都有允许来源及有限推导，规则更新也有法定或已声明的建模根据。它不是“已经穷尽现实法律的一切来源”，也不是`origin`只有两个构造子的穷尽归纳。

## A9. 数学复用与不复用

继续使用FiniteMonotoneIteration处理固定输入下的单调子问题；保留Horn与有界论证生成；保留经过条件核验的Dung/ASPIC+元理论；保留ExactExpr并补法定表达式构造；保留来源与工程安全保障。尤其应复用FullMath论证生成中实际的`generate_sound`和`generate_complete`，不要只看到ULM08的过滤合同就重新造一套。

不把Banach作为法律唯一裁判的总原理。某数值子模型满足完整的度量、完备性与收缩前提时可以使用；这些前提不能由“我们需要收敛”反过来指定。优先级变化、新证据和新旧法转换通常会改变结论集合，不能继承add-only结论单调性。

不把LegalRuleML/LKIF当作已验证的中国法。使用其表示资产、类型组织和交换格式，法律语义与文本对应仍由本模型和具体规则族负责。

## A10. 法律统一验收的最终问题

把同一事实中的主体、法律行为内容、否定、期限性质或规范版本改变一项，系统是否能依法改变相应关系，并说明是哪一条构成／变动规则导致的？反过来，只改变文件名、运行编号或当事人脱敏名称，法律结论是否保持？

**回答前一问，才是在建设法律模型；只回答后一问，仍主要是在建设工程保障。两者都要有，但不能以后一问冒充前一问。**

## A11. 把共同结构写成可检验的数学语义，而非又一个外给gamma

### A11.1 同一法律理论的语法与解释

一个法律判断至少属于下列互不混淆的种类：基础事实、概念归类、规范适用、现存法律地位、权能、证据评价、负担分配、法律变动、裁判拘束。规范的结论类型决定它是事实推理、规范产生、制度性变动还是证明／程序规则，不能任意跨型。

在同一签名下，规则的共同形式是`r=(κ,vars,A,kind,effect,exceptions,source)`。但是语义不是一句“gamma(r)为真”。必须逐个解释`kind`：

- **构成规范**：满足该规范的事实／行为模式，在其语境中构成一种法律身份或关系。不是因为事实描述和法律概念共享一个字符串就构成。
- **行为规范**：在适用条件下，为指定关系的指定主体产生具有内容和时段的义务、禁止或许可；规范存在不推出已履行。
- **变动规范**：指定事件和其法律效果条件满足时，对指定关系实施增设、移转、消灭、暂停等操作。对其他关系的作用必须另外有规则。
- **证明及程序规范**：规定某争点由谁承担何种负担、依据何种标准和程序进行认定，以及认定对何人何事项具有何种效力；不把其结果等同于历史事实无条件为真。

对严格规则，模型必须满足对应的条件式。对可废止规则，保留可撤销的支持，再按实际例外、攻击位置和优先规则确定可接受分支。严格规则可靠性、可废止支持和最后接受性分别证明，不能把从前件可推导的候选直接宣布为不可推翻的法律结论。

统一的实质是：这几类规则可以在受类型约束下互相作用。例如构成规则产生合同关系，行为规则据此产生给付义务，证据规则决定履行争点的可用认定，变动规则据履行消灭对应债务，责任规则仍可对先前违约产生另一责任关系。**不是先有五个系统各自的最终答案，再组合五个答案。**

### A11.2 两种更新必须在数学对象中区分

设`H`是法律上相关的事件历史，`B`是关于该历史的证据／认定依据，`Tκ`是采用的规范解释。系统求解的是这一语境下允许的法律解释集合，而不是一个预填状态：

\[
\mathcal{S}(T_\kappa,H,B)
=\{X\mid X\text{满足该语法的规范、变动和可废止接受语义}\}.
\]

此处“满足”必须由上一节的规则种类及其具体解释递归定义；严禁在工程中仍实现为任意`gamma : X → Prop`，只把这行公式打印在论文里。

新增证据改变`B`，可以改变我们对先前事件及其效果的评价；依法发生的新事件扩展`H`，依规范产生新的法律地位。若要改变既有裁判拘束，则需要相应法律事件与规则，不能靠重算研究判断自动替代。

模型可以有多个可接受分支。查询可以问“所有分支都支持什么”“哪些分支支持什么”“分歧来自哪个法律解释／事实认定”。若分支集合未算完，报告计算未完备；若依法评价终了但争点事实不明，进入相应负担规则。不能把这两种情况合并为同一空集。

### A11.3 法律生成性与视图一致性的真正证明目标

需要证明的生成性命题是：每个正式主张的法律地位都能回溯到实际规范实例，以及它使用的基础事实、证据评价、权能／事件和中间关系；每个关系变化都能指出相应变动规则。证明树中叶子的输入类型和法律地位必须明确；不能把待求争议结论本身作为基础叶子而不披露。

还需要证明：视图的相互作用来自同一关系实例和同一规则实例。例如对一项满足法定清偿条件的债务，债权人“要求继续清偿该已消灭债务”的地位和债务人“仍须清偿该债务”的地位应同步退出；先前违约引起的另一赔偿关系是否保留，须按责任规范决定。不能在两个输出列表分别人工删除，再把列表一致说成法律统一。

最后，证明实现计算与这个独立定义的法律语义相符。**语义定义、法律规则编码、相对于语义的数学证明、生产执行结果四者均要落地；任何一层缺席，其他层的绿色都不能填补。**

## B2. 五座桥：按法律命题重写任务

### L1　违反、责任、救济：取消一般性的“违反→攻击”

**现状反例。**`directViolation`不读取事实内容和义务内容；全面履行事实也可满足其谓词。现有`contract_breach_direct_violation_shape`只是该简化定义的可构造性，不能背书真实违约认定。

**新增语义。**到期不履行、瑕疵履行、预期违约分别建模。以到期不履行为例：同一主体和义务实例、义务适用且未被履行／免除等效果消灭、履行期条件、依合法证据判断的未履行。未找到履行证据不是自动的未履行事实。责任还需适用的归责、因果、免责或减责规范；违反不会自然消灭原义务。

**Lean目标形状。**新增规则语法必须提供`ViolationDerivation κ rel issue`，其构造子引用实际的违反规则及前件证明；另定义行为轨迹与规范内容的`SatisfiesDuty`语义。目标为：`ViolationDerivation`可靠映射到规定违反语义；按约、按期全面履行的同一义务实例不满足“到期不履行”谓词；该反例不得靠另贴`notBreach=true`标签拒绝。用独立定义的轨迹条件证明，而不是把“不履行”结论放进`WF`字段。

**已有依赖。**LegalSyntax、DDLDefinitions仅供迁移对照；严格前件闭包复用Horn；有界法律证明树复用FullMath的`generate_sound/complete`。

**证明形状／难度。**违反规则分情况，按实际规则推导树归纳，反例验证；高。**失败路径。**保留“在已给定违反假设下的后果计算”，明确不输出已认定违约；目标和范围不删除。不能继续以旧`directViolation`成功替代。

### L2　例外、抗辩和攻击位置

**新增语法。**`ExceptionEffect`至少区分否认基础事实、否认法律要件、阻却规则适用、否定责任、减少责任或金额、阻却请求行使、程序性障碍。救济是否择一、权利是否已经消灭不能全变成二元攻击边。

**独立目标。**定义`LegalAttack κ a b site`，其中`site`是被攻击的实际前提、规则应用或后果位置。`compileAttacks`的可靠性／完整性必须为：其输出存在该合法位置及对应规则实例，反向对受支持语法中的每个`LegalAttack`都能生成边。不是给`LegalAttack`直接定义为“在编译结果中”。条件性减责须编为后果变换，不能使全部责任一并退出。

**依赖与形状。**复用ULM08结构载体并补rule membership；复用ULM09/10作为已解析击败图下游；参考R05、R06的攻击分类和理性条件。对规范实例和攻击类型归纳，高。未解决的例外保留争议分支，不能自动当成不起作用。

### L3　冲突优先与协调

**现状。**`DefeatPolicy.succeeds : TypedAttackV1 → Bool`外给，没有位阶、特别关系、新旧法适用或协调理由的推导。ReceiptAuthority是工程制品等级，不是法源位阶。

**新增语义。**优先必须绑定冲突的规则、适用语境和理由；规则之间允许不可比。规范有效性、规范适用、规则优先与论证偏好分层，不合并为一张权重表。协调模式产生允许共同满足或调整作用域的法律条件，不一定删除某条规范。

**目标。**编译器接受的击败决定对应同语境的优先推导；不适用规范不得仅因位阶高而击败适用规范；协调分支的结果满足双方被保留的约束；改变语境可能改变优先结果，而纯工程重命名保持结果。分支不可比时禁止任意补全全序以求唯一答案。

**依赖与形状。**ULM09 `mem_resolveDefeat_iff`和ULM10解析桥可作末端；新的法律优先推导必须先完成。依规则种类归纳并证明攻击编译与相应ASPIC+政策的条件对应，高。未决优先继续显式产生未决分支，不伪造Bool。

### L4　证明责任进入认定与后果

**现状。**ULM12 `ValidFor`不约束finding的证据依据；`withFinding`能改变finding而保持有效。JC的`adjudicate_v5`同样消费外给认定。另一个计数型`BurdenTracker`只查证据数，本轮没取得它在生产路径被调用的证据。

**新增定义。**`EvidenceAssessment`必须索引到同争点、同证据集、同阶段、同规则版本；`BurdenDerivation`从实际法律规则分配责任；`StandardSelection`从规则选择证明标准；`DecisionReadiness`来自程序事实和相应规则。人作出的争议证据评价可以作为显式、可追溯的判断输入，但不得把它宣称为形式系统自己证明的案件事实。

**目标。**从负担分配、证据评价和阶段规则产生`FindingDerivation`，再生成对应的法律后果；移除`withFinding`这类“不重验证即可更换认定”的入口。认定未满足时只能适用该争点／负担主体的后果，不能任意读取一个非程序性状态。合法评价终了后的事实不明，可以产生法定负担后果；求解器中断不能代替这套前提。

**已有依赖。**复用`UnifiedV2/LegalInterfaces`的就绪／未知／后果不改写事实区分；ULM12四分输出继续作为输出层，不让该层反过来定义实体认定。概率支持参考R08，不用统一百分比自动认定所有案件事实。

**证明形状／难度。**负担规则推导归纳，争点和主体一致性，证据更新引起评价重算；高。降级为明确条件性分析或待法律判断，不能默认驳回，也不能因一个无关分支的求解超时阻止已独立成立的程序性处置。

### L5　时间、适用和法律变动

### T2　将最小性收编有限单调内核，并修正Horn模型桥

**精确候选陈述：**

```lean
namespace FiniteMonotoneSystem
variable {α : Type} [DecidableEq α]

def LeastPrefixedTarget : Prop :=
  ∀ (sys : FiniteMonotoneSystem α) (s : Finset α),
    sys.step s ⊆ s →
      iter sys sys.univ.card ⊆ s
end FiniteMonotoneSystem
```

证明先做任意`n`的`iter sys n ⊆ s`归纳。零步为空，后继由`step_monotone`和`step s ⊆ s`传递。再取card步；由`fixed_at_card`证明结果是固定点，由两次包含证明最小不动点唯一。包内`KernelLeastnessCandidate.lean`给出无占位证明的候选实现，仍待固定工具链编译。

**关键纠错：**通常Horn规则模型的判准是`TH(M) ⊆ M`，不是`TH(M)=M`。模型可以含不由规则推出的其他真原子。不能按照旧HANDOFF把全部模型等同于不动点。正确桥是：规则模型等价于前不动点；最小规则模型与从空集得到的最小不动点相同。

已有依赖：`iter_succ`、`step_monotone`、`fixed_at_card`、`HornSystem.TH`及`horn_result_fixed_point`。难度低—中；失败时保留已有Horn／Dung各自最小性，不宣布通用目标已闭合，亦不削弱目标。

### T3　机器可达性、终止和合法完成不是同一件事

**现有机器的精确可达性目标：**

```lean
namespace JurisLean.ULM

def MachineHaltingTarget : Prop :=
  ∀ (g : TypedGraph) (c : RunConfig),
    ∃ r : SemResult, Run g (.running c) (.halted r)
end JurisLean.ULM
```

终止量取运行态`|g.edges \ completedEdges| + 1`，停止态为0。每次edge步必须是图内未完成边，所以剩余边数严格下降；finalize下降至0。没有可启用的良构边则用`Quiescent`停止。证明任意合法步的度量严格下降，从而无无限合法步链；存在性另用有限选择一个可启用边构造。实现调度器需要与Step关系精化，不能单凭存在某条终止路径声称所有生产调度都终止。

**另一个法律缺口不能被终止掩盖：**当前Step只有edge和finalize，未完成／失败结果分支没有相应到达构造；图“静止”也可能是缺材料或缺依赖。新增合法完成判据应检查本任务要求的法律推导是否存在；若只达到静止但任务未完成，应构造incomplete，不是settled。

已有依赖：`applied_edge_not_reenabled`、`run_preserves_request`、`halted_has_no_step`；Finset差集基数严格下降API待固定Mathlib核验。难度中。保留有界未完成状态不是砍范围；不得把“空图立刻停机”当作业务任务已完成。

### T4　非单调更新：撤回事实、加入抗辩、修改优先、新旧法与裁判变动

**参考合同要独立。**更新先作用于法律输入和法定效果，得到child规则／证据／论证态势；结果再按所选语义完整定义。优化实现应证明等于该child参考结果。不能把`∀ delta, implementation delta = reference delta`作为前提，再取一次`h delta`叫证明算法正确。

新增更新类别：撤回某来源的事实支持、撤回规则、加入或撤销抗辩、优先理由变化、规范适用版本变化、依法发生的关系变动、依法撤销或改变有拘束力认定。前六类改变“当前能推什么”，最后一类涉及“既存裁判效力如何改变”；两者不能用一个删除缓存操作替代。

现有AF层可先给独立精确目标：

```lean
namespace JurisLean.ULM
noncomputable def AFUpdateCorrect
    (algorithm : DefeatAF → DefeatAF → SemanticProfile → Finset (Finset ArgId)) : Prop :=
  ∀ old child profile,
    algorithm old child profile = extensionsForProfile profile child

```

它只是待证明的算法规格，不是成品定理。实例化时必须提交实际实现，不能令algorithm在定义上就是reference后宣称优化增量已证明。

### T5　combineAssurance的代数律

原函数返回`Option AssuranceEnvelope`，并非同一类型上的全定义二元运算。应先明确共同scope上的纤维，或显式提升到Option后证明。

```lean
namespace JurisLean.ULM

def mergeAssuranceOption
    (x y : Option AssuranceEnvelope) : Option AssuranceEnvelope :=
  x.bind fun a => y.bind fun b => combineAssurance a b

def AssuranceLawsTarget : Prop :=
  (∀ x y, mergeAssuranceOption x y = mergeAssuranceOption y x) ∧
  (∀ x y z,
    mergeAssuranceOption (mergeAssuranceOption x y) z =
      mergeAssuranceOption x (mergeAssuranceOption y z)) ∧
  (∀ x, mergeAssuranceOption x x = x)
end JurisLean.ULM
```

逐状态证明scalar合并的三律；Finset并的三律；scope相等／不等分类；最后做结构外延。若两个scope不等，用none吸收规则处理，不可以悄悄取左方scope消除冲突。已有依赖：ULM14合并定义和scope拒绝性质。难度低—中。

**法律边界：**这个半格合并是保证信息的保守合并，不是证据证明力合成理论。不同独立证据可能相互印证，不能将`min`误用为“法律证据聚合永远不能增强”。

### T6　weightedMetricSpace完备性和收缩桥

已有weightedSupDist正性、对称、三角不等式及分离点，已有明确MetricSpace实例。缺的是**这一实例**的CompleteSpace，不是默认函数空间实例。

```lean
noncomputable def WeightedCompleteTarget : Prop :=
  ∀ (n : Nat) [Nonempty (Fin n)]
    (w : Fin n → ℝ) (hw : PositiveWeights w),
    letI : MetricSpace (Fin n → ℝ) := weightedMetricSpace w hw
    CompleteSpace (Fin n → ℝ)
```

候选证明：`x ↦ (fun i => x i / w i)`双射到标准有限Pi的sup度量空间；证明为等距，再通过满射等距传递完备性。备选是逐坐标Cauchy和有限sup控制。等距传递完备性的确切Mathlib API及实例参数位置**[待核验]**；不得凭记忆打印“已可编译”。

接着对实际数值算子`f`证明weighted距离下Lipschitz系数`K`及`K<1`，再构造该实例下的`ContractingWith K f`。不能从默认MetricSpace取得ContractingWith后不加桥接地应用到weighted空间。

已有依赖：WeightedSupNorm、BanachComplete、ULM15四条ContractingWith包装。难度中。失败时使用已证明的有限／精确数值方法，保留收缩桥待证，不修改法定离散选择来强行得到收缩。

### T7　grounded的标准语义链

```lean
namespace JurisLean.ULM

def GroundedStandardTarget : Prop :=
  ∀ (af : DefeatAF), af.WellFormed →
    ConflictFree af (groundedExtension af) ∧
    Admissible af (groundedExtension af) ∧
    Complete af (groundedExtension af) ∧
    (∀ s, Complete af s → groundedExtension af ⊆ s)
end JurisLean.ULM
```

证明从空集admissible起，建立对admissible集合应用characteristic仍admissible，依赖防御定义和载体边界，然后对迭代次数归纳。card步固定点推出complete；对任意complete，用其固定点条件与`groundedExtension_least`取得包含。可额外证明这些纯图性质所需条件比`WellFormed`更弱，但面向法律的出口仍须绑定真实良构论证。

禁止把“固定点”直接等同“无冲突”。相互攻击的两论证全集可以是固定点但并不无冲突；最小性才是grounded结果的特殊结构。

已有依赖：`empty_admissible`、`groundedExtension_fixed/least/subset_args`。难度中。不能把Admissible直接新增为Grounded定义字段后宣布新增证明已完成。

## C4. 五类形式化边界：正面处理，不以“边界”隐藏未做任务

**逻辑边界。**对无限或循环结构必须声明可判定／有界片段及元理论条件。有界生成必须报告深度／载体限制；求解未完备不等于实体失败。范围声明不得拿来删掉任务清单中的已承诺法律构件。已有Horn／Dung的有限证明仍有实际价值。[季312–25、1183–86；R04]

**认识论边界。**证据准入、事实真实性、统计预测和因果归责分开。不能把来源哈希或机构文本直接当真实事实；相互印证与共同来源重复不能混同。保留证据缺口、反证和因果模型假设，并在合法就绪阶段依法分配不明风险。[季2666–68；判9268–69；R07、R08]

**语言边界。**事实陈述和法条解释可能存在多种语义。输出候选解释、差异位置、依赖规则和采纳理由，不用“人工最终判断”这句话把所有法律理解外包成一个Bool；可形式化的明确前提和限定词仍须自动检查。[季3183–94；德88076–137；R11、R14]

**规范边界。**冲突的权利或价值不保证有唯一总分。不强加全部权利的全序，也不能因比较困难就完全不记录理由。把实际可以识别的优先、协调和不可比形式化；对争议采用明确解释分支和责任人。[季150–53；判117–25；R15]

**权力与伦理边界。**法律上有何职权、程序上如何救济、技术上由谁触发执行必须分别表示。数学模型不能因自身置信度高而获得裁判权能；也不能把它不喜欢的有效法律行为直接改成无效。保留机构行为、复核、撤销及责任的结构。[季1166–70、14844–52；R02、R03]

## C5. 六类播报保证怎样回到正确位置

失败保留、未完成携带义务、扩展空性证明、输出不冒充裁判、工程保证不升级和重复不洗白污染，都保留。它们解决“系统怎样不乱说”，并未解决“法律上为什么成立”。

法律模型新增的上层验收是：实质推导的每一步均有明确法律语义，和主体、时间、程序、证明、责任关联；播报只能忠实反映该推导。不是将六条安全定理直接改名为六条法律定理，也不是删掉这些安全工作从零重来。

## C6. 十四法律族的全量要求

`LEGAL_FAMILIES_14.json`已划定十四族，全部必须保留在施工范围。其“所需研究”现在不能继续留成一串标签后宣布family完成。

每族要提交：实际纳入的法源范围及版本、构成规范、地位及变动、负担与标准、例外／抗辩、期间／过渡、责任及救济、非金钱效果、正例／反例、与共同法律结构的映射。逐族明确已表示／解释待核／未表示的规则；不把未审核书证填进去取得“全量完成”。

全量目标不等于可以谎称本轮已将整部中国法穷尽编码。验收应同时说明“共同法律结构及注册任务是否全部实现”和“实际采用哪些具名法源中的哪些规范”；禁止拿前者替后者，也禁止用几个原子示例冒充十四族完整规则包。

# D　蒸馏记录的法律数学消化协议

## D0. 目标与输入事实

按附件报告，wave1方法库有40,428条、78源；wave3与wave4合计28,597条，wave4新增18,815条，涉及133册和约45.7M源文字符。全库“约七万”是近似资产规模，不是本轮重新点验结果。不能把40,428与28,597的和当成已经精确核验了所有wave的无重复全库总数。

本轮没有用户私盘上的records、bodies、manifest和源书正文。坏引／缺引为0是附件的审计报告值，不是本轮执行结果。**引文正确，只说明摘取忠实；不说明书中观点是现行法、适用本案、事实真实或已经获得司法采纳。**

协议的最终产品不是七万条“已证规则”，而是：带原文和法律解释依据的规范候选、经过采用审查的规则实例、可执行的数学任务，以及保留下来的方法／争议／经验资产。所有材料均被处理，但不强迫所有材料都成为规范。

## D1. 统一落地目标

每条真正进入形式推导的规则，都落到A报告同一法律语法：主体和角色、关系实例、行为或事实模式、前件、适用范围和时间、例外作用点、法律地位／变动／责任／救济结论，以及实际来源。

方法指引可成为“争点检查方法”，案例分析可成为“解释候选及适用事实差异”，律师经验可成为“策略与反例”，模板可成为“文书生成资产”。它们不因此获得普遍规范效力；不被当前Harness消费的资产仍保留在工作台储备。

`LegalRuleML`用于交换表示，LKIF用于概念组织，R11／R14用于抽取参考，R12用于可算法化法条和测试结构。没有一个外部工具的输出可以直接跳过本协议的法律语义核对。[SOURCES.md：R10—R14、S01]

## D2. 数据对象：不再只存ruleText与verified

## D3. 阶段一：原件与说话者识别

读取现有records/bodies/manifest，不重造全部存储格式。确认引用能回到原文，保存原始件和版本；去重以来源和引文关系为依据，不能把同一内容从多本书转引算作多个独立法源。

记录首先分为法条原文、司法解释／规范文件、裁判要旨、裁判理由、当事人主张、专家解释、律师经验、统计／预测模型、操作方法、文书模板等。一本判例书里的“原告认为”不能自动变成“法院认为”，案例书的“分析”也不能自动获得裁判理由身份。

**验收断言：**每个候选至少有一个可解析锚点；知道是谁在何种文本中主张该内容；无法确定说话者或文本身份则保留待核。记录处理成功不自动提高法源效力。

## D4. 阶段二：法律意义切分与结构提取

按照“一个独立法律判断及其必要限定”切分，不机械按句号或token长度拆开。跨段落的“但是”“除外”“前款”“该规定不适用于”必须保留连接。把同一法条的条件和例外拆成两条互不相认的候选会制造错误规则。

抽取任务必须保留：肯定／否定、主体角色、量词、比较符、必要条件与充分条件的区别、且／或、时间起算及届满效果、推定／反证、举证责任种类、救济是并行还是择一、选择权属于谁。

**验收断言：**候选中的每个有法律意义的常量／关系有来源锚点或显式推导依据；抽取器新增的隐含前提标为解释候选，不能伪装成原文。金额绑定“何人基于何关系支付什么”，不是只保留数字集合。

“十三维”在这里用作漏项检查，不要求每条记录都填写十三份重复内容。某维不适用必须说明原因，不自动补造信息。

## D5. 阶段三：回查法源和适用版本

通过法规库定位被引用规范及适用版本，必要时核对官方公开原文。审查本书是在引用条文、概括条文、提出学说，还是转述个案处理。书证不存在官方规范对应不意味着没有价值，但不能标为“法条规则”。

回查范围包括法条交叉引用、例外、过渡条款、法域和事项适用范围。不能只找到相同编号就通过；旧法与新法可能编号相同内容不同。书中对法条的解释和法条本身分开存，未核验部分为候选输入。

**验收断言：**正式规则实例绑定确切源版本和解释身份；不能因某文献较新便自动取代有效规范，也不能因来自法院网站就把网页中的所有文字都视为规范正文。

## D6. 阶段四：冲突分组与法律采用审查

按法律问题、关系类型、规范版本和语境分组，保留不同来源的差异。不要多数投票去掉少数观点，更不能以多个模型同意替代法源或解释理由。

人工审查放在真正需要法律采用判断的地方：共同规则模板的法律含义、存在解释分歧的条件／例外、复杂证据标准或因果判断、跨法域迁移、会改变权利义务的自动化解释。模板和稳定规则族可按批次审核，随后具体参数可由确定性检查器验证；不是要求人逐条点七万个“同意”，也不是让模型替人作七万次法律采纳。

**验收断言：**每条已采用规则能说明采用了哪个解释、适用范围、排除哪种解释及其理由；未解决争议不得变成默认False。人对某法律规则的采纳不等于人已为任意案件事实作出认定。

## D7. 阶段五：形式检查和规则实例化

从共同法律语法编译，不直接生成任意Python或Lean程序后执行。LLM输出视为不可信候选数据，不执行源文中的命令、脚本或提示词。未经类型和语法校验不得进入编译器。

检查项包括变量绑定和类型、主体关系、前件方向、显式否定、法源版本、时间范围、例外位置、责任和救济结构、单位和金额绑定。采用有限语法或受限语法时必须记录限制，不能超范围后悄悄猜测。

**形式保证准确表述：**如果独立语义中的规则模板已经证明可靠，且本实例的代入、前件、来源采用范围都经相应检查，那么由该实例构造的推导相对于这一语义可靠。这并不证明自然语言到模板的翻译永远正确；翻译正确性仍依赖D4—D6的证据和审查。

需要新增`compileCandidate_sound`一类实际编译器定理：经检查的候选产生的规则确为被采用解释的实例；不能将`Verified`简单定义为该结论，再给验证器加一个“它是正确的”参数了事。

**验收断言：**正式推导使用的规则可逆向定位到已采用实例；没有任何只靠`verified=true`、`witness≠""`或`reviewer≠""`构造法律有效性的入口。测试可以把这些标记都填真，但缺少实际规则、前件或语境时仍须拒绝。

## D8. 阶段六：法律反例与独立期望

正例和反例从法律解释定义产生，并由独立审查确认预期，不由同一个模型同时写规则、写预期并自评通过。

必测变化包括主体互换、否定翻转、且／或改变、法定期限与普通时间参数混淆、起算事件改变、履行事实改为未履行、证据缺失与反证成立区分、免责与减责区分、诉讼时效与权利存续期間区分、法源版本改变、同款不同条件、并行／择一救济改变。

对单位和金额，除ExactExpr类型检查外，还需检验赔偿项目是否合法、范围如何确定、能否并行、抵扣及上限是否适用。确定值、裁量区间和条件性金额不同型输出。概率、评分与统计模型不得直接进入正式金额公式，除非具体法律规则允许且该模型经过独立验证。

**验收断言：**每个规则族有“法律内容变化→相应结果变化”的测试，也有“纯工程名称变化→法律结果不变”的测试；二者缺一不可。变异测试必须实际生成并执行变异体，不能把一组畸形输入测试重新命名成mutation score。

## D9. 阶段七：进入JC、Harness及工作台

JC使用规则实例构造实际论证和法律关系变动；Harness只按争点组织材料与解释结果。工作台保存规则、采用理由、反例、输出和复盘；方法资产、经验与文书风格继续保留，不因无法转成Horn规则而丢弃。

新规则输入不是直接填`successConsequence`或`finding`。从规则到事实评价、请求基础、抗辩效果、责任、救济和数额的连接必须显式。某项争点需人工判断，则给出具体待判断事项、已有证据与结果差异，不用抽象的“请人确认全部”逃避工程。

**验收断言：**渲染后的文书与JC推导保持同一主体、关系、条件、金额、时间和结论强度；从“已编译”到“法律成立”之间没有无依据的跳转。

## D10. 阶段八：更新、回撤与旧结论保存

规则解释被修改、法源版本变化、事实证据被撤回，不能只追加新记录而保留所有旧后承。根据实际依赖撤销或重新评价结论；同一结论另有独立有效支持时不能一并删除。具体算法按B的非单调更新任务证明。

旧裁判文书和历史输出保留原始语境及版本，不用新法或新解释回写历史证据。重新研究的结论与依法改变既有裁判效力分开；后者需要特定法律事件和程序依据。

**验收断言：**当前结果等于child语境的独立重算语义；历史记录字节不被新结果伪装覆盖；归档旧名不被误判为活跃引用故障。

## D11. 预测功能必须回应四层批判

| 批判 | 协议回应 | 禁止的捷径 |
|---|---|---|
| 预测不等于决策 | 将事实概率、法院行为预测、法律规范结论和策略效用分别建模；预测不直接签发法律地位 | 把“胜诉80%”等同“请求成立” |
| 准确率没有合适基准 | 声明样本范围、时间切分、法域、标签来源、朴素基准、校准和区间；没有就只记模型候选 | 给一个无基准准确率用于宣传 |
| 灾难性错误不能平均 | 按错误法律效果、金额、自由／身份等后果分层评估，另列严重错误及漏检；平均分不抵销致命错误 | 大量简单题正确掩盖少量严重违法结论 |
| 训练集截断和反馈偏差 | 按案件／来源簇及时间隔离，记录未公开与未起诉案件缺失；新数据独立检验，不把生成结果回灌当真标签 | 同源转引分散到训练测试；只用成功公开案例推断总体 |

在没有真实数据、标签核验和外部验证的本轮，不宣布概率系统已校准，也不编造风险数值。数学概率公式可保留并施工，但经验有效性明确未证。

## D12. 全量交付的回执形状

提交源记录总清单和逐条处理状态，处理状态包括规范候选、采用规则、方法资产、经验／争议资产、重复来源关联、待回查以及无法表示。不得为了取得“七万条全部完成”删掉无法表示的记录。

每一组正式规则实例必须带：源版本、解释采用依据、共同语法实例、形式检查结果、法律反例和实际JC调用结果。没有这些工件，就只能说“已提取候选”或“形式检查通过”，不能说“法律数学消化完成”。

本协议面向现有records/bodies/manifest工作流增补语义层，保留所有资产，不新建大型分布式平台，不要求五Agent默认并行。默认单执行者＋必要的独立法律核验；法学争议需要判断时明确到问题，不依赖模型数量制造可信度。
