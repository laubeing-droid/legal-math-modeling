# 05 文献谱系：形式化与复验的外部惯例

> 目的：回答审计结论"台账统一了，数学没统一——它是一堆互不引用的结果"，以及owner的要求"别人是怎么写的，怎么复验的，去查，别自己编"。
> 本文只做一件事：把外部成熟做法与可核实的出处摆出来，并逐条对照本仓有什么、缺什么。不提出自创方案。

## 0. 核实口径（先说方法，免得本文自己成为一条无凭主张）

本轮所有条目按三档标注：

| 档 | 含义 | 核验手段 |
|---|---|---|
| 已核实 | 元数据或源码文本本轮直接取回并读到 | Crossref REST API（`api.crossref.org/works/{doi}`、`query.bibliographic`）、arXiv Atom API（`id_list`、`search_query`）、GitHub REST API（`/repos`、`/git/trees`、`/contents`）、raw 源码/README 原文 |
| 部分核实 | 取回到了载体，但关键细节（确切假设、是否覆盖某情形）未逐行读源码 | 同上，仅 README/摘要级 |
| 未核实 | 本轮检索未取回可信记录 | 必须写"未核实"与原因，禁止补一个看起来合理的编号 |

本轮实际发生的五处"看起来对、其实错"的编号（其中四处真实可解析、只是对象不同；最后一处根本不解析），记下来当反例：

- `arXiv:2401.15170` → 实为一篇 LLM 定性编码论文，不是 Scholze 的 LTX 写作。
- `arXiv:2109.07828` → 实为 sterile neutrino 物理论文，不是 ECHR 判决预测论文。
- `arXiv:2211.10503` → 实为等离子体激波论文，不是基准泄漏论文。
- `10.1214/07-AOS504` → 实为 Fan & Fan 的高维分类论文，不是 Shafer–Vovk 的 conformal 教程。
- `10.1038/d41586-023-00957-5` → Crossref 未解析。

结论：**"能解析"与"解析到正确对象"是两件事**。只查 HTTP 200 的门禁必然放行这类错误（见第 5 节）。

**B. `leanblueprint` / `plastexdepgraph`——把 blueprint 变成工具而不是手工艺**

- 仓库：`PatrickMassot/leanblueprint`，许可 **Apache-2.0**，默认分支 `master`，最近推送 2025-12-23（活跃），描述"plasTeX plugin to build formalization blueprints"，安装为 `pip install leanblueprint`，依赖 graphviz 与 `plastexdepgraph`（`PatrickMassot/plastexdepgraph`）。README 原文已取回。
- 来源说明：README 写"originally created in 2020 for the Sphere Eversion Project"，随后列了 30 余个采用项目（LTX、PFR、FLT、Con-NF、Banach–Tarski、Carleson、CLT、Brownian motion 等）。这是"多项目共用一套呈现层"的既成事实。
- 节点状态词汇表（README 的 `\graphcolor` 默认值）：`stated` / `can_state` / `not_ready` / `proved` / `can_prove` / `defined` / `fully_proved` / `mathlib`。**"陈述已形式化"与"证明已完成"是两个独立状态**，这正是打散孤岛所需要的最小词汇。
- 溯源宏：`\lean{...}`（LaTeX 节点 ↔ Lean 声明名）、`\leanok`（该环境已完全形式化）、`\uses{...}`（依赖，用于生成依赖图）、`\proves{...}`、`\notready`、`\discussion{<issue number>}`（每个定义/陈述挂一个 GitHub issue 讨论位）、`\mathlibok`（已并入 mathlib）。
- 命令：`leanblueprint new|pdf|web|all|serve`，其中 **`leanblueprint checkdecls`：验证 blueprint 里出现的每一个 Lean 声明名都真的存在于本项目或其依赖（含 Mathlib）中**（需先 `lake build`）。
- 这一条对本仓最关键：本仓已经出现"header 声称某 CI 工作流认证了它"的失效。`checkdecls` 是同一类失效的工具级封堵——名字不存在就红。

**C. PFR 形式化项目——多人协作下的定理级状态跟踪**

- 仓库：`teorth/pfr`，许可 **Apache-2.0**，最近推送 2026-09-27（活跃），描述"Repository for formalization of the Polynomial Freiman Ruzsa conjecture (and related results)"。
- 原文献绑定：README 直接把项目锚到 `arXiv:2311.05762` = W. T. Gowers, B. Green, F. Manners, T. Tao, "On a conjecture of Marton"（arXiv Atom API `id_list` 已核实），以及 `arXiv:2404.09639` = Jyun-Jie Liao, "Improved Exponent for Marton's Conjecture in F_2^n"（已核实）。
- 阶段化叙事：README 明写"第一阶段（PFR 本体）已完成 → 第二阶段（推论 + Liao 把指数 12 降到 11）已完成 → 当前阶段（推广到其它 bounded torsion 群 + 指数 9）"。**项目状态按阶段写在 README，不靠记忆。**
- 配套工件：blueprint（`https://teorth.github.io/pfr/blueprint`）、方法文档（`.../docs`）、Zulip 专流、`PFR/Examples.lean` 作为结果的可执行示例、`PFR/ForMathlib/`（含 `Entropy/`、`FiniteRange/` 等）作为"预备并入 mathlib"的暂存层。
- T. Tao, "Formalizing the proof of PFR in Lean4 using Blueprint: a short tour", *What's new*（wordpress），2023-11-18（正文已取回）。要点：
  - 依赖图是**自动从 blueprint 生成**的，用途是"a rough snapshot of how far along the formalization has advanced"；白底绿边 = 陈述已形式化、证明未形式化。
  - 反向修正：形式化过程中发现必须补"非空"假设，于是回写 LaTeX blueprint（"will update the LaTeX blueprint shortly to reflect this"）。即**自然语言侧被机器侧纠错**。
  - 文档页会把定理 pretty-print 出来，同时保留 `Source` 链接显示原陈述；README/博客都提醒 pretty-print 会隐藏类型信息。

**E. Isabelle/AFP——"像期刊一样运作"的收录门槛（门槛清单最完整的一份）**

- `isa-afp.org/about/`（正文已取回）：AFP 是"organized in the way of a scientific journal. **Submissions are refereed**"；条目"are tested and maintained continuously against the current stable release of Isabelle. Older versions … remain available"；列出 9 位编辑（Abdulaziz、Blanchette、Klein、Lammich、Lochbihler、Nipkow、Paulson、Thiemann、Traytel）。
- `isa-afp.org/submission/`（门槛逐条，正文已取回）：
  1. **禁用 `sorry` 与 `back`**。
  2. 实例化里不得出现 Isabelle 生成名（如 `xa`），要用 Isar / `subgoal` / `rename_tac`。
  3. **禁用 `sledgehammer` 与 `smt_oracle`**。
  4. `nitpick` / `quickcheck` / `nunchaku` 调用必须带 `expect` 参数（或全局设 `expect`）——即**计数器示例搜索也要被固定成可复验的断言**。
  5. `apply` 脚本按子目标缩进；只有具名引理才允许挂 `[simp]` 之类属性。
  6. 用 Isabelle linter 在提交流程中检查大部分违反；其它反模式在 build log 末尾警告。
  7. 必须有 `ROOT` 文件、与条目同名的 session、全部在 `chapter AFP` 下、每个理论文件至少属于一个 session。
  8. 必须在**当前 Isabelle/AFP 发行版**跑通并生成 PDF 文档；给出的验证命令是 `isabelle build -v -o browser_info -o "document=pdf" -o "document_variants=document:outline=/proof,/ML" -D <entry dir>`。
  9. **"The entry should cite all sources that the theories are based on"**——引用完备性是收录条件。
  10. 每个 session 必须有超时，且超时粒度必须是 5 分钟的整数倍（`divisible by 300`）。
  11. 必须有网页摘要（abstract）；标题里禁用 MathJax。
  12. 鼓励复用其它 AFP 条目（有标准引用写法），并鼓励标出"可能适合并入 Isabelle 发行版"的部分。
  13. 接收后作者**有维护义务**（或指定维护人）。
  14. 更新要"mostly monotone"：只加不改，改动影响他人条目时必须先与其沟通。
  15. 重大变更要写进条目 metadata 的 `extra-history` 关键字。
- 条目页固定披露（以 `Nash_Equilibrium`、`Sigmoid_Universal_Approximation`、`Neural_Networks` 三页实测为例）：作者与邮箱、日期、摘要、**License**、Topics、Session 及其理论文件清单、Used by（**反向依赖**）、三份 PDF（outline / document / `session_graph.pdf`，即 session 依赖图）、Dependencies、可直接复制的 BibTeX（`journal = {Archive of Formal Proofs}`, `ISSN = {2150-914x}`, `note = {\url{...entries/X.html}, Formal proof development}`）、按 Isabelle 版本冻结的历史发布列表、Related publications（带 DOI）、AI 辅助声明（`Nash_Equilibrium` 页 Note 原文："Codex with gpt 5.5 on xhigh reasoning was used to help with proof engineering … The final definitions, statements, and proofs are checked by Isabelle"）。
- 引用格式官方样例：M. Jaskelioff and S. Merz, "Proving the Correctness of Disk Paxos", *Archive of Formal Proofs*, June 2005, `https://isa-afp.org/entries/DiskPaxos.html`, Formal proof development（取自 `isa-afp.org/help/`）。

## 2. 复验的证据合同：什么才算"这条主张被验过"

外部把"发表"与"被验"分开，靠的是可机械检查的槽位。逐条给出处：

**C1 独立性：认证必须由与被认证对象不同的主体/路径完成。**
- AFP：条目由作者提交、由编辑 referee，且由 AFP 的自动测试流水线持续对着当前稳定 Isabelle 版本跑（`isa-afp.org/about/`、`/submission/`）。
- mathlib：作者不能直接 merge；Bors 把 PR 合到 `staging` 后由 CI 构建，`bors.toml` + `docs/workflows.md`。
- ACM：`Results Reproduced` 定义明确写"by a person or team **other than the authors**"（见 C5）。
- 本仓对照：AGENTS.md 已把"GitHub Actions 是唯一 Lean 权威"写成边界，方向一致；缺的是"被认证文件与 commit 的配对断言"（见 C3）。

**C2 陈述不能被证明偷偷改写。**
- Palomar Registry（`https://palomar-registry.org/about`，正文已取回）原文：机械检查用 Comparator 验证"所记录的正式证明在所指定 Mathlib 版本下确实证明了所记录的正式陈述"，且只用当前 Comparator 配置允许的公理；导出的证明**同时经 Lean 内核与独立的 NanoDa 内核重放**；"The comparison is performed using the Comparator tool, which **holds the advertised statement apart from its proof, so that a proof cannot quietly weaken the statement it claims to establish**."
- 同一站点对自身限度说得比多数仓库清楚："The review is a filter: it may identify a blocking problem, or it may find no blocking problem. **It does not accept, approve, or endorse a result.** Palomar adds no human editorial step: no one here reads the mathematics the way a referee would."、"Palomar asserts nothing beyond these three checks."
- 采用面证据：`teorth/pfr` README 有专章说明 `PFRPalomar/Challenge.lean` / `PFRPalomar/Solution.lean` / `comparator.json` / `formalization.yaml`（`Challenge.lean` 文件确经 GitHub contents API 取回）；另有 `Arthur742Ramos/nash-equilibrium-lean`（BSD-3-Clause，2026-09 活跃），描述"Lean-native finite Nash equilibria formalization prepared for Palomar"。
- 需要注意的口径冲突：pfr README 称 Challenge 模块里"六处刻意的 `sorry`，是 Comparator 惯例"。这是"陈述侧占位、解答侧真证"的两文件结构，与本仓"任何 `sorry` 即失败"并不等价。**移植时必须说清是哪个文件的 sorry**，否则会把本仓的红线讲错。

**C3 被认证的 commit 必须真的包含被认证的对象，且时间不得早于它。**
- 最接近的外部机制是 mathlib 的 `export_crossrefs.lean` → `crossrefs.json`（**嵌入 mathlib commit SHA**）+ 每次合并后由 `export_crossrefs.yml` 重跑；以及 AFP 的"条目按 Isabelle 版本冻结历史发布"。两者都把"证据"钉在一个不可复用的版本标识上。
- Palomar 的表述同样直接："records mathematical claims **from fixed versions of their source files**"。
- 本仓对照：`build_run_identity.py` / `build_ci_run_index.py` 已解决工作流↔commit 配对，但**没有"该 commit 的文件树里确有该模块、且该模块的 blob 版本等于被引用的版本"**这一层。审计里的失效（配对为真、主张为假）正是缺这层，而非缺前一层。

**C4 文档不得比生成物更旧。**
- 直接可用的一条：mathlib `lint-style.lean` 的头注释声明它**额外检查"scripts 目录下每个文件都在其顶层 README 中有文档条目"**。这就是"生成的账户文件因文档漏写其生产者而失真"这类问题的现成门禁：把"谁生产了它"写成可检查项，而不是靠记得。
- 本仓可立刻换用：对 `program/`、`docs/formal-release/`、T-spectrum 台账等生成物，加一条"每个生成物必须由某个脚本声明为输出，且脚本必须在文档里被列名"的互检。

**C5 徽章语义（ACM）。**
- ACM 政策页 `https://www.acm.org/publications/policies/artifact-review-badging` 直连返回 403（Cloudflare），本轮经 Wayback 取回同一页正文，故记为"内容取自存档副本"：
  - `Artifacts Evaluated – Functional`：artifacts 被认定 documented、consistent、complete、exercisable，且"include appropriate evidence of verification and validation"。
  - `Artifacts Evaluated – Reusable`：在 Functional 之上，结构与文档质量显著超出最低要求，严格遵循社区规范。
  - `Artifacts Available`：artifacts 被永久公开可获取。
  - `Results Reproduced`：主要结果由**作者以外**的人/团队在后续工作中**不使用作者提供的 artifact** 独立获得。
  - `Results Replicated`：主要结果由作者以外的人/团队**部分使用作者提供的 artifact** 获得。
  - 政策还写明：两种情形都不要求逐位相同，只要求在该类实验可接受的容差内一致。
- 对本仓的直接含义：**"CI 绿"至多是 `Artifacts Evaluated – Functional` 的证据，绝不能写成 `Results Reproduced`。** 本仓 AGENTS.md 的"回归测试只证明后端健康、不证明当前主张"与此同构，可用这套词写得更可核。
- **未核实**：`POPLAC`（POPL 的 artifact 存档/清算所）本轮在 GitHub 检索 `POPLAC artifact` 命中 0，acm.org 又被 403 挡住，**不写其语义**。

**C6 软件必须可引、可钉。**
- V. A. Smith, D. S. Katz, K. E. Niemeyer, FORCE11 Software Citation Working Group, "Software citation principles", *PeerJ Computer Science* 2:e86 (2016), DOI `10.7717/peerj-cs.86`（Crossref 已核实；预印本各版本 DOI `10.7287/peerj.preprints.2169v1..v4` 亦已核实）。建立的是：软件引用要给到"可定位到版本"的粒度。
- 本仓对照：`CITATION.cff` 已存在；缺口是"每次对外主张时给出被主张 commit + 该 commit 上 artifact 的 digest"，而不是仓库级 citation。

**C7 存档层。**
- 已核实：`softwareheritage.org` 与 `about.zenodo.org` 站点本轮均可达（HTTP 200），前者定位是长期源代码存档、后者为版本化 DOI 存档；**但两者的字段级要求本轮未逐项核对**，故只作为"存在这两条外部存档路径"记入，不写具体规则。

**C8 收录即要求引用完备。**
- AFP 门槛第 9 条（1.1-E）："The entry should cite all sources that the theories are based on"。本仓的对应缺口：`paper/references.bib` 只服务论文层，Lean 文件头部只写 Copyright/Authors，**没有"这个定理的数学来源是哪一篇、哪个定理号"的槽位**。mathlib 的 docstring bib key → References 页（1.1-D）是可直接照搬的形态。

外部对本仓这类数字的**写法要求**，可以直接落到两份已成文的规范上（已核实）：

对本仓那个具体数字，可辩护写法（全部由上面的出处支撑，不是自创）：

1. **抽样框**（datasheet 字段）：明确写出"二审民事"这一审级与案由范围、地域与法院级别覆盖、时间窗、以及"哪些年份的文书公开规则不同"——本仓语料每行带 `judge_date`，条件具备。
2. **时间切分**：频率必须按年份分组给出，而不是给一个合并数；否则违反 non-exchangeable 前提（4.2 最后一条）。
3. **患病率**：给出分母与标签定义，并同时给"未分类/不可判定"的比例。
4. **不确定性语义**：区间是覆盖语义（4.1），不是"胜诉概率落在区间内"。
5. **不能读成什么**：不能读成"胜诉率"（标签是文本匹配到的裁判结果，不是当事人胜败的构造效度度量）、不能读成总体、不能读成因果。
6. **复算路径绑定**：数字旁给出产生它的脚本、输入清单 digest、被绑定 commit。这一条是第 2 节 C3/C6 的直接应用。

## 5. 引用与标识符核验的工作流建议

### 5.1 可机械检查的字段（Crossref）

`api.crossref.org/works/{doi}` 单条可取回的字段：`DOI`、`title`、`container-title`、`author[].family/given`（或 `name`）、`issued.date-parts`、`volume`、`page`、`type`、`ISSN`/`ISBN`、`URL`、`publisher`。检索端点 `works?query.bibliographic=` / `query.title=`。官方文档已迁至 `https://api.crossref.org/`，GitHub 上 `CrossRef/rest-api-doc` 的 `rest_api.md` 顶部有 **DEPRECATION NOTICE** 并指向新址，另要求遵守 etiquette 与 `api_tips.md`（本轮已取回 README 原文）。

### 5.2 三步核验（第 2 步是关键，多数假阳性的门只做到第 1 步）

1. **解析**：`GET api.crossref.org/works/{doi}` 返回 200，或 arXiv `id_list` 返回对应 entry。
2. **对得上对象**：把返回的 `title` 与台账里存的标题做归一化字符串比对（大小写/Unicode 兼容/连字符折叠后），再比对第一作者姓氏与年份。这一步拦掉"DOI 真实但指向另一篇"的整类错误——第 0 节的 4 个实例全部在第 1 步会通过、在第 2 步失败。
3. **对得上用途**：台账里每条引用记下"被引用于哪个主张"（本仓可用现成的 `[@key]` 语法，见 `check_paper_claims.py` 的 `CITE_MD_RE`），主张改动时引用被重新评估。AFP 把这条写成收录条件（1.1-E 第 9 条）；mathlib 把"引用键"塞进 docstring 并渲染 References 页（1.1-D），使"声明 ↔ 来源"可在库内被检查。

### 5.3 版本与状态

- 预印本 vs 期刊版要同时登记（本文第 4 节 Angelopoulos–Bates 两条 DOI 并存即示范）。
- 软件要版本可钉（`10.7717/peerj-cs.86` 的原则）；仓库级 citation 不足以支撑一次具体主张。
- 存档路径存在两条外部选择（SWH / Zenodo，站点可达已核实，字段级要求未核实）。
- **未核实**：POPLAC 的徽章/存档语义。

### 5.4 已知失效模式（本轮实证，可作为门的测试用例）

| 失效模式 | 本轮实例 | 门的对策 |
|---|---|---|
