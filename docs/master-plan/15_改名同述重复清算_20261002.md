# 15 改名同述重复清算（2026-10-02）

> 本卷只作**裁决规则与逐族处置**。条数一律不写死：权威计数归
> `docs/formal-release/statement_duplication_census.json` 的 `duplicated_statement_types`
> 与 `cross_family_statement_types` 两个字段，由 `scripts/ci/build_statement_duplication_census.py`
> 重算并 --check 复算。手写条数等于给一本会变动的账做保，本仓已两次因此替假账背书。

## 〇、这件事的口径先说清

比对键是**剥去声明名之后的归一化陈述体**（`build_statement_duplication_census.py:85` 起，
`body = rest[named.end():]`）。因此本卷谈的"重复"只有一种含义：**两处声明的陈述逐字同型**。

它能证明的仅仅是字面重合。展开定义后才相同的两条（restatement），以及把同一结论换个
参数化写法的两条，本门一律看不见——普查账里 `headers_missed_by_scanner` 那一项就是这条盲区
的自报，本卷继承同一盲区，不假装看得见。

所以"改名同述"这个说法在本卷**不是缺陷的同义词**。四条陈述相同而名字不同的声明，
完全可能是四个不同立场各自需要的署名。判"要不要动"的依据是下面四族，不是"重复了几条"。

## 一、A 族：契约槽位名 ↔ 模块内描述名 ⇒ 双名保留，禁止合并

形如 `CORE_nn_*`／`COMP_C0n_*`（都在 `ULM16TheoryComposition.lean`）与某模块里那条
描述名陈述同型。已核样例：`CORE_02_admitted_premise_status` ↔ `admitted_wf_has_admitted_status`、
`CORE_01_typed_transition_request` ↔ `localTransition_preserves_request`、
`CORE_08_branch_nonmixing` ↔ `different_branches_not_composable`、
`COMP_C01_trust_nonupgrade_left` ↔ `trust_meet_le_left`、
`COMP_C02_observation_preservation` ↔ `preserves_comp`。

**裁决：两条都留，一条都不许删、不许改名、不许改成 re-export。**

理由不是美学。`ULM16TheoryComposition.lean` 那批 `CORE_*`／`COMP_*` 是**内核复用合同的槽位名**——
复用账（`kernel_reuse_report.json`）正是按这些具名槽位记账的，把槽位名并掉等于把合同的抓手拆掉。
换句话说这一族的"重复"是合同面的**双署名**：一份陈述既服务模块叙事，又服务合同槽位，
两个名字各自被不同的账引用。合并会制造一段没有任何账能读到的空档。

**这一族不计入"概念未归一"**。它记为"同一事实、两处署名、各有读者"。

## 二、B 族：外部忠实移植件内部的重名 ⇒ 本仓无权动

出现在 `External/GameTheory/**` 之内的全部条目，含两种子形：
同一文件内两个名字陈述同型（`pushforward_comp` ↔ `pushforward_pushforward`、
`pmfPi_cond_coord_other_marginal` ↔ `pmfPi_cond_coord_push_other`），
以及同一名字在两个文件各有一份（`runDist_eq_of_stepIndependence`、`sum_mul_pmf_ne_top`、
`append_singleton_inj`；该子形的其余条目以普查账 `duplicates` 映射为准，本卷不转录名字——
门对其中两个名字报"no such declaration"，说明它们的声明形状不在本门的识别口径内，
宁可不写也不写一门核不动的名字）。

**裁决：本仓不拥有这些名字的处置权，一律不改。**

理由：这些字节是 `elazarg/GameTheory@107085bc4` 的**忠实拷贝**，认定口径就写在 03_ 卷的
"40 件同 pin 字节忠实拷贝"那一条上。一旦本仓为了命名整洁去改名或删重，provenance 就断了——
那等于用本仓的命名偏好去污染一个外部认定对象，之后任何"移植件已认定"的说法都不再成立。
同名跨文件在 Lean 里由 namespace 隔离，本来就不是构建缺陷。

## 三、C 族：本仓内部的真改名同述 ⇒ 登记，但动刀要过"已证核心"这一关

不含 `CORE_*`／`COMP_*`、不在 `External/` 之下、两处都是本仓自取名的条目。已核样例：
`TH_subset_univ` ↔ `horn_operator_subset_univ`、`TH_monotone` ↔ `horn_operator_monotone`
（`HornDefinitions.lean` 与 `HornFixedPoint.lean` 各一份）；
`grounded_is_least_complete` ↔ `grounded_is_least_fixed_point`（**同一文件**
`DungFixedPoint.lean` 的两条）；`bb5_trustLE_trans` ↔ `trustLE_trans`
（`Seams/BoundaryBridge5.lean` ↔ `Seams/BoundaryClosure.lean`，这一对正是把比对键去名之后
才被抓到的那条）；`rate_num_le_den` ↔ `successes_le_length`（同一文件 `Mandate/Kernel.lean`）；
`candidate_cannot_enter_verified_fact_gate` ↔ `candidate_evidence_not_accepted`；
`comp_preserves_inclusion` ↔ `composition_preserves_inclusion`；
`reject_doc_caseId` ↔ `wrong_case_rejected`、`reject_doc_debtor` ↔ `wrong_debtor_rejected`。

**裁决：这一族才是"未归一"的候选，但本轮只登记不动。**

约束来自 AGENTS 的变更红线：`HornFixedPoint`、`DungFixedPoint` 等属**已证核心模块**，
无返例或构建失败不得重写。而 `bb5_trustLE_trans` ↔ `trustLE_trans` 这对还额外被
`Seams/BoundaryBridge5` 的可达性账引用。所以动刀的前提是：先证明两处引用者都能跟着改名，
再单独立卡执行。本轮把条目登记在册，不改名、不删除、不改陈述。

## 四、D 族：跨模块家族的那一条 ⇒ 这才是需要桥的地方

`clipped_conservation`（`FullMath/GenericKernels.lean`）与 `split_residual_identity`
（`BusinessRelationsDelta.lean`）共享同一条 ℚ 恒等式 `max r 0 - max (-r) 0 = r`，
是全仓唯一一条被门判为跨家族的同述（`cross_family_statement_types` 那一项）。

**裁决：登记为待桥，且不许用"删掉一条"来消解。**

理由：这两条**读数是不同的**——一条在说"截断后的守恒"，一条在说"业务关系增量的分流"，
共享的是一个算术事实而不是一个法律概念。把它们并成一条，等于宣称这两个法律读数是同一件事，
而那正是本模型不许未经证明就说的话。桥的形制应当与 13_ 卷 C 类一致：一条把两个读数连起来、
并说明它们何时可互换（以及何时不可）的定理。

## 五、同名两份（本仓内部）

`FullMath/GenericKernels.lean` 与 `FullMath/Representation/FiniteCertificates.lean`
之间存在**同名且同述**的两份：`enumeration_member`、`exact_check_reflects`
（另有 `enumeration_accepted` ↔ `enumeration_certified`、`partial_check_sound` ↔
`partial_scan_sound` 两组异名同述，已计入 C 族）。

**裁决：并入 C 族的处置**——同名两份意味着后一份没有复用前一份，属真冗余；
但两文件都不在冻结清单内，可以改，改前须确认 `check_declaration_collisions.py` 与
可达性账能跟着重算，且不得借改名顺手扩大陈述或缩小陈述。

## 六、本卷不主张的事

1. 本卷**没有**减少任何一条陈述，也没有让重复计数下降；它给的是"哪些重复是制度、
   哪些重复是债"的判据。A、B 两族明确**不算债**。
2. 本卷的判据不可机器化到"该不该合并"这一层：是否同一概念取决于法律读数，
   机器只能核"陈述逐字同型 + 是否跨家族 + 是否落在冻结模块"。
3. C、D、五这三族的具体清算尚未执行，逐条清单以普查账的 `duplicates`／`cross_family`
   两个映射为准，本卷不复制条目全集（复制即多一份会过期的账）。
