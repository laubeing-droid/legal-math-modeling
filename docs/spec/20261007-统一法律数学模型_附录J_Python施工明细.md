## J.0 本轮理论修订的执行路径

本件依修订主文§2–§12施工，不再把“另给有限化/另选混合求解器/另补非线性表示”留在关键路径。以下名字均为拟新增项目函数，选定算法不是未核实的第三方API。

1. `build_argument_grammar → saturate_summaries → solve_quotient_extensions`：输出有限文法、δ、Q及摘要见证，完整树用可按需展开的文法纤维表示；source/path身份不被q替换。grounded/complete/preferred/stable按主文精确回拉，资源限制不变成树高截断。
2. `build_local_cards → enumerate_assessments → derive_standard_certificates → finalize_issues`：原始材料生成有限卡片值/理由摘要，独立理由树保留；终结按法定阶段全表求值，返回两轴状态及逐条Exhausted4见证。所用普通支持profile和特别法规则来自主文§5/§11，不收全案高概率/排尽怀疑位。
3. 数量AST进入`RealFormula`，不把变量限定为Fraction；常量精确有理，实代数点为整系数平方自由多项式及有理隔离区间；解析概率/exp/log用区间及显式精度算法。实际付款与债务人/保证人程序受偿范围分账。
4. 共同尝试行动域→事件核→真实事件更新→可见E→法律重评→同一后果效用；策略按信息集。规范推荐、描述性违法动作、实际发生不合并。

**已经选定的非线性执行依赖。** 使用QEPCAD B的C++命令行，Windows构建采用已经核对CMake源码和包含SACLIB的 [PetterS/qepcad提交23b1e7e4ccca7e2ebe470b1d4a70f2844d77590a](https://github.com/PetterS/qepcad/tree/23b1e7e4ccca7e2ebe470b1d4a70f2844d77590a)，其数学算法来自Collins/Hong/Brown QEPCAD。未来构建包需锁CMake/MSVC与产物依赖，携带上游许可证和测试；本轮未安装/编译/运行它。直接调用exe的stdin/stdout，不复用该仓老Python wrapper：已核它把Equivalent误译Implies且用eval解析输出，不能进入本模型。

输入编译器从有限AST生成合法变量名、自由变量优先的有序列表、自由变量数、前束实数公式和句点；有理常数清正分母，代数系数先引入满足最小多项式及唯一隔离区间的新实变量，再存在量化；保持原量词依赖。已核上游tests/test_problem1.txt的基本协议为 `[title]`、`(a,b,x)`、`2`、`(Ex)[x^2+a x+b=0].`、后续控制命令。实际执行在投影前发送`proj-operator (c,...,c)`（变量数−1个c；单变量无需），`full-cad`、`afupbri E`；推进到Before Solution（phase e）时独立发送`solution-extension T`选择普通Tarski语言，再按完成协议结束。这些在固定版本help/dispatcher及实现实际存在。`afupbri E`的E指精确整数根隔离，仅接受E/H；它与`solution-extension E`的扩展根语言不是同一选项，不能改成非法的`afupbri T`。禁用measure-zero-error、删投影因子和只保全维单元的路线，法律等号/零边界不能丢。[固定命令源码](https://raw.githubusercontent.com/PetterS/qepcad/23b1e7e4ccca7e2ebe470b1d4a70f2844d77590a/qesource/source/qepcad.help)

输出由小型语法解析器读取Tarski公式/代数点，不eval；解析器的往返、量词及布尔保义独立证明和差分。退出错误、非法/残缺公式或遗漏nullification属于技术失败Failed，不能当FALSE。无技术失败的资源中止有已核C/L且W非空时为SoundPartial，否则Paused。独立精确校验路线是附录I的完整CAD分解：核对投影集合、Sturm计数及每层sections/sectors覆盖和原式/输出式真值一致。全算法存在及终止依据主文§6.3.1–2；I.0.1的C0–C5全部必交。QEPCAD若不能导出所需完整证书，使用已经选定的全投影/提升和参数Sturm回构参考生成器，从同一输入生成分解及普通RealFormula，再由独立checker检查。外部输出只作加速候选，不能成为无法补齐证书的唯一完成来源；不把“再调用同一QEPCAD比较”当独立验证。线性片段继续复用Farkas/Fourier–Motzkin；无界整数只在Presburger片段走逐变量Cooper消元（系数公倍数、边界及模同余代表有限化），不把任意整数非线性送实数求解器。

Beta整数用精确CDF；正有理/半整数和有限混合依主文§7.4尾界、内部导数界和双点缩区。CDF输出[a,b]为有证外包；仅b₁<q更新左端、a₂>q更新右端，未分离继续细化，粗显示相等不准剪枝。b<1左尾系数不得误取1；η=2^(−k),k≥2，先把尾宽压到ρ/4，再固定η按L̄选N≥max(1,ceil(4L̄ℓ²/ρ))和点值精度，ρ≤εβ/4、β为B(a,b)有证正下界。η减小同时随意加N不保证总误差下降。它是严格递增Beta域的完整精度算法，不自动推广至真实平坦CDF。一般非可忽略选择的后验保留联合积分/有证界，不能仍套Beta计数。混合Nash、序贯一致信念、共同后果argmin都编译为实闭域公式；exp/log目标仅按明确模量给ε证书，不假称QE支持。

## J.3 文件安排和公开入口

就近修改上表既有模块。拟新增业务/参考模块只有两项：

- theory/spec/canonical_v2/case.py：规范化案件、规则政策、阶段结果及 JSON 边界，供双方共享不可变数据类型。
- tools/unified_math_v2/reference/legal_semantics.py：独立法律判断关系的有限解释与组合检查，禁止 import unified.pipeline 或调用 run_case、step_event、evaluate_joint、solve。

新增测试放既有 tests/spec、tools/unified_math_v2/tests、tools/full_math/implementation_tests，以实际职责组织，不按 U 编号建三十个文件。需要拆分时按有独立调用者的数学职责拆，不写一次调用的工厂/策略框架。

公开入口拟在既有 unified/pipeline.py：

~~~python
# 接口草图：CaseInput 等是 case.py 拟类型，不是现成 API。
def run_case(case: CaseInput, env: LegalEnvironment, *,
             limits: ExecutionLimits) -> CaseRun: ...

def step_event(state: ProcessState, event: CaseEvent,
               env: LegalEnvironment, *, limits: ExecutionLimits) -> StepRun: ...

def run_trace(initial: ProcessState, events: tuple[CaseEvent, ...],
              env: LegalEnvironment, *, limits: ExecutionLimits) -> TraceRun: ...
~~~

事件可能产生多个允许后继；StepRun 保存 (next_state, next_env) 对的集合或精确符号表示，run_trace 对各允许前态及其绑定环境应用局部关系后再做有证明的观察等价合并，不能强制单值。预算耗尽保留未处理分支。规范更新后的下一步使用 next_env，不能继续传入原始 env 而让版本回流空转。

run_case 不收最终 AAF、自由裁判集合、固定 amount/payoff 作平行权威输入。政策提供具名局部规则和授权判断，中间结果由内部构造产生。

## J.4 规范化输入、结果和精确 JSON

| ExecutionLimits | 搜索节点/时间/内存预算，与语义深度、主体/规则域分开，不能修改法律解集 |

新 IdKind 成员要与 Lean 类型、manifest、解析器共同迁移，不能假装已存在。结构身份用类型 ID 与作用域元组，不用只含结论文字的字符串。

initial_state 是某一声明时点及事件前缀后的状态快照，携带其来源与规范环境身份；后续 events 必须接在该前缀之后，不把旧历史再算一次。run_case 从此状态求当前案件问题；step_event 验证状态、环境及事件作用域匹配，合法规范变更同时产生新状态与新环境。回放时按成对后继传递，不能把一个分支的状态与另一个分支的规范版本拼接。

规则语法采用主方案规定的类型化原子、显式否定、有限合取/析取、有限域量化、具名程序/效果规则及有定义域的数量表达式。专业判断是带范围的数据记录，不是回调或“全部结论正确”开关。

### J.4.3 精确 JSON 与舍入

有理数编码 {"n":"-17","d":"100"}，分母正，输出约分；大分子/分母用十进制字符串避免下游失真。天数/计数可用类型合同内 JSON 整数，拒绝 bool。日期明确历法、粒度与时间含义。

边界拒绝重复键、NaN、Infinity 和 JSON 小数进入精确通道；有意测量小数用十进制字符串和声明精度解释，不把 float 打印成字符串冒充原始精确值。

下段是待纳入 types.py/case.py 的可执行关键代码，只检查 JSON/分数，不认证法律：

~~~python
import json
from fractions import Fraction

def _unique_pairs(pairs):
    result = {}
    for key, value in pairs:
        if key in result:
            raise ValueError(f"duplicate JSON key: {key}")
        result[key] = value
    return result

def _reject_number(value):
    raise ValueError(f"non-integer JSON number in exact input: {value}")

def load_exact_json(text):
    return json.loads(text, object_pairs_hook=_unique_pairs,
                      parse_float=_reject_number, parse_constant=_reject_number)

def fraction_from_json(value):
    if type(value) is not dict or set(value) != {"n", "d"}:
        raise ValueError("expected rational object")
    if type(value["n"]) is not str or type(value["d"]) is not str:
        raise ValueError("rational components must be decimal strings")
    n, d = int(value["n"]), int(value["d"])
    if str(n) != value["n"] or str(d) != value["d"] or d <= 0:
        raise ValueError("noncanonical rational components")
    return Fraction(n, d)

def fraction_to_json(value):
    if type(value) is not Fraction:
        raise TypeError("Fraction required")
    return {"n": str(value.numerator), "d": str(value.denominator)}
~~~

实现优先复用仓内重复键拒绝逻辑，不复制多个版本。输出 allow_nan=False、UTF-8、schema_version。只规范化集合顺序；事件顺序、合法政策顺序不可统一排序去重。

拟改 exact_numeric_contract.round_minor_units(amount: Fraction, mode: str | None) -> NumericReport，兼容旧整数调用。HALF_UP/HALF_DOWN 对绝对值中点后恢复符号；DOWN 向零、UP 远离零；其他政策另命名。可执行关键算法：

~~~python
from fractions import Fraction

def round_fraction(value: Fraction, mode: str) -> int:
    if type(value) is not Fraction:
        raise TypeError("Fraction required")
    sign = -1 if value < 0 else 1
    q, r = divmod(abs(value.numerator), value.denominator)
    if mode == "HALF_UP":
        up = 2 * r >= value.denominator
    elif mode == "HALF_DOWN":
        up = 2 * r > value.denominator
    elif mode == "DOWN":
        up = False
    elif mode == "UP":
        up = r != 0
    else:
        raise ValueError("unknown rounding policy")
    return sign * (q + int(up))
~~~

舍入位置由表达式节点和政策指定，禁止每步擅自截分。Python 3.12 官方 [fractions 文档](https://docs.python.org/3.12/library/fractions.html) 说明 Fraction 的整数/字符串精确构造及从 float 构造的语义；[json 文档](https://docs.python.org/3.12/library/json.html) 给出 parse_float、parse_constant、object_pairs_hook 和 allow_nan，支持上述边界实现。文档不是法律解释或模型正确性的依据。

## J.6 具体算法如何写

### J.6.1 主链组装

以下为接口级伪码，名字均对应本附录拟函数。关键是后段只消费本案前段结果；独立检查器读取原输入与见证。

~~~text
run_case(case, env, limits):
    normalized = parse_and_validate_case(case, env)
    legal = knowledge_view(normalized)
    selections = build_norm_selection_relation(legal, env)
    branches = []
    for selection in enumerate_norm_selections(selections, limits):
        selected_env = bind_norm_selection(env, selection)
        ivl = instantiate_rules(legal, selected_env, selection)
        cards = build_local_cards(legal, ivl)
        for assessment in enumerate_assessments(cards, ivl.shared_constraints):
            # 连续参数保留符号约束；不枚举实数，不预填全案证明标准。
            reasons = instantiate_reason_rules(legal, ivl, assessment)
            horn = strict_horn_projection(reasons, rule_licensed_bases(legal, ivl))
            closure, derivations = horn_closure_with_provenance(horn)
            grammar = build_argument_grammar(legal, reasons, closure, derivations)
            summaries = saturate_summaries(grammar)
            defeats, pending = compile_summary_defeats(summaries, reasons, selected_env.policy)
            for extension in solve_quotient_extensions(summaries, defeats, limits):
                standards = derive_standard_certificates(assessment, extension, reasons)
                bases = admission_bases(legal, ivl, standards, extension)
                adjudication = finalize_issues(bases, legal.stages, ivl)
                rulings = derive_rulings(legal, adjudication, ivl)
                effects = derive_effects(legal, selected_env, rulings)
                quantities = solve_quantity_problems(
                    amount_constraints(legal, effects, selected_env.policy))
                branches.append(branch_with_witnesses(selection, ivl, cards, assessment, derivations,
                    grammar, summaries, defeats, pending, extension, standards,
                    bases, adjudication, rulings, effects, quantities))
    outcomes = union_branches_preserving_shared_parameters(branches)
    analysis = run_requested_analysis(
        legal, env, outcomes)
    return assemble_run_with_dependencies_and_pending(
        legal, selections, branches, outcomes, analysis)
~~~

规范选择必须先分支，A/B互斥不能把其规则一起送入Horn。closure传文法只作索引，严格结论保留完整规则子树及原叶来源；不得将派生p改成无来源新公理，逃脱对其前提的攻击。

某次请求不要求分析可以明确“未请求”，但原定分析机制仍须全部施工验收。外部不得传入全链正确、完备或可采纳全集作为流水线成功条件。

上述for只表示已选算法的完整语义；执行器须传播每个迭代器的Complete/SoundPartial/Paused/Failed状态，不能把预算耗尽当迭代结束。无扩展、没有合格局部评价、未决争点与未处理分支分别保留。各分支共享参数的联合约束先组合再投影，不能逐争点独立取值后拼出不存在的案件。

上述拟 `knowledge_view` 对应附录 I 的 `lawView`，不从不可观察的 R 派生法律求值参数。公开入口虽持有带初态的案件，裁判及其数量/分析后段只能接收该知识视图；独立参考关系也从同一受限视图解释，不能借原始 `case` 偷看 R。事件语义更新实际状态另走 `step_event`。必须补成对合成测试：只改变不可观察 R、保持知识视图和环境相同，全部裁判观察保持不变。

### J.6.3 Horn、论点和攻击

Horn 复用现有有限闭包。需要性能优化时在 horn_logic.py 就地用前提计数工作队列，并记录触发规则与子依赖；独立检查器采用满足全部严格规则的模型集合：小域枚举包含初始事实的闭合赋值，求其共同后承，不调用 horn_closure/horn_step。

论证身份复用unified/arguments.py；在该文件就近补文法产生式、有限摘要及δ饱和。每个新摘要记录叶或(rule,childSummaryIDs)构造见证；队列只处理新摘要及受影响规则，至多全部有限摘要新增次数。独立checker由见证重建实际树，再验规则前提/身份/site；完备依据主文一般证明，小域有限树枚举仅检实现反例。无根循环Q为空、有根p⇒p的完整语言无限而Q有限；不能把Q节点称唯一树身份。

攻击编译逐对Q及七类site检查，规则/来源/权限/范围/程序许可带实际实例键。完整树解释独立检查器不用edge_impl；rebut/undermine用原Last-set优先，其余五类按法定靶点，不将未知许可改成已阻却。优先未知保留解释分支或MissingInput，不按字典序补赢家。

七类攻击逐行消费主文§4.3的读取合同。每个typedEdge保存kind及可回溯到完整目标树的site/规则引用见证；checker重建该具体kind的独立关系，再核优先/作用域条件，不只比较无类型邻接矩阵。合成破坏逐类替换Mode、LeafKind、ground实例、guard种类/slot、主体权限、时间法域、程序阶段及ProofUse/来源，确认该边依独立语义改变；在合法祖先上提升同一攻击则应保持。这里扩现有攻击用例，无需另建一套注册表。

Dung求解用显式Q全集，不能丢孤立摘要。grounded有限迭代，complete/stable枚举全部子集，preferred取包含极大admissible集；输出q逆像语言。完整树f与Q的q分开。超预算返回未完成及已证范围，不缩小域；空stable族不得真空全称输出支持。

### J.6.4 入场、程序与裁判

burden_ref 决策表是受授权政策的一种算法，不能把任意整数 priority 排序视为法律冲突规则。同优先且有冲突而法律未决定时保留允许结果集合/待定。

拟在 unified/burdens.py 增加 admission_bases、apply_issue_policy，采用有限具名规则数据，核心为：

~~~text
对每个争点：
  读取作用域匹配的政策、阶段和已完成评价
  分别计算普通支持、免证/自认、推定、终局各入口
  对每项入口应用自身反证、撤销、妨碍和权限阻断
  保存仍有效的依据集合，不汇成一个普通支持位
  由具名规则决定继续评价、采纳、拒绝或不利后果
  将规则真正产生的后果送入请求/裁判规则，不直接认定历史真值
~~~

现 resolve/resolve_scenario 将 established 以外状态送 policy.failure，须针对评价是否完成、阶段是否就绪、未知是否依法触发负担逐项重审。无评价不等于评价完成后举证不能；不利后果必须携带其程序规则依据。

实际理由图按主文§5.3.6在求扩展前生成RawAnswer/RawCompare及其七类击败见证；答案标签无实际defeat不算回答。扩展后才求Cmp/StrictSuperior（正向In且反向非In），不反向补图。遍历全部实质反证，Out者保存攻击树，In/Undec者保留未解决；Strong相反理由以同身份兼反证角色，防止不同局部赢家拼出双标准。用途/标准纳入键，普通优势只作用普通标准；民事特别排疑和刑事替代不能借该优势自动Out。

adjudicate只在已证明适用的算子域使用递推，不把全部法律机制硬压为Dung grounded。撤回和救济等非单调变化作为事件重建当前问题，固定输入终止与跨事件更新分开。

连续裁量保留允许域；只有完整集合基数 1 或独立符号单点证书可以报唯一。无解、单元素空扩展集、未扫完且 found 为空严格区分。

### J.6.5 后果、数额与符号域

pipeline 构造 EffectSet；kernel.transfer 只在其形成型裁判片段使用。履行、抵充、清偿、撤销和程序拘束分别处理：“未新增关系实体”不等于“余额和履行状态未变”。

拟在 exact_numeric_contract.py/precision.py 就近补数量 AST 解释器：constant、add、sub、mul、defined_div、min/max、piecewise、round。节点带单位规则与基数来源，返回精确值/域和实际依赖，不设置自由回调。

实际收款GrossReceived允许超过实体债额；Satisfied依法冲抵，TitleEntitlement记录当前有效名义，不用独立实体重算私自抹去。纯现金差分另定义`Rcash=b−GrossReceived_for_this_basis`，其中收款按已声明归属/观察范围关联本基数，排除无关流入，却不预先截到b；`Ccash=max(Rcash,0)`、`Ucash=max(−Rcash,0)`，故Ccash−Ucash=Rcash。本金100同一基数实收140时Ucash=40；它不直接等于已到期返还债。法定Remaining由Entitlement/Satisfied/Title及减免/执行规则产生，RestitutionDue另依无合法根据、执行依据撤销等要件。实际效用计真实现金轨迹，规范可给付域按合法余额与有效名义约束。

分段利息按本金事件、利率变更、起止/停止事件和合法日界切段，各段 base×rate×day_count/denominator，最终按政策节点舍入。单利/复利、日数约定都来自具名政策，不默认猜测。

区间复用 iv_add/iv_mul。除数区间含零时按原语义输出无定义分支或分裂区间，不造有限精确零。支持域由原合同决定，不能把困难分支排掉后报全域精确。

### J.6.6 概率、统计与因果

主查询优先复用 reference/core.BayesNet 的变量消去，独立检查用枚举；共享数据类型和精确算术，不共享核心消元过程。调用前核准 enumerate_query/eliminate_query 的实际签名。

Observation 有稳定身份和来源族。重复同一观察不二次更新，同源派生不当独立证据相乘；撤回后使相关派生特征/查询失效，无关部分可复用。

P01—P13/E01 工作全列如下：

- P01/P02：条件表非负、每行归一、父域和拓扑完整；Z=0 返回证据不兼容，不全零后验。
- P03：VE 与独立枚举比完整分布和证据边际，不只比预测标签。
- P04：观察身份、同源依赖、撤回失效实际进入查询与证书。
- P05/P06：选择可忽略的共轭子域才作精确Dirichlet/Beta计数；一般抽样用主文联合选择似然，条件独立S⊥Y|θ不足以删选择因子。有限超先验按每组实际证据边际重权。
- P07：平均以证据边际重权；稳健界覆盖全部保留模型；模型类未完整不声称全类界。
- P08/P09：污染/剩余质量来自实际处理范围，非法质量或分母为零分别报告。
- P10：整数参数CDF可精确比较；一般正有理/半整数有限混合用主文双点缩区，比较包围端点b₁<q或a₂>q，未分离保持区间并细化。Δ/2证明每步最终获得证书，宽度至多乘2/3；不得把粗读数相等冒充有证弱比较来剪枝。积分内部交集为空直接0，CDF在x=0/1直接0/1。输出CDF区间/分位区间各有自己的包含证书，不靠判断F(mid)=q终止。
- P11：目标、cluster、预测时点、特征可见时点、标签发生时点同时检查，ID 不交不足。
- P12/P13：精确 Brier；主 PAV 块合并，独立检查单调、加权残差和 KKT，不以若干样本比较冒充全域最优。
- E01：真实评估运行器的输入、分割、指标、区间和声明政策必须实现；本任务只用合成测试。无真实材料时经验义务仍外部未完成，不能用合成得分关闭。

EXT06 复用 extended_algorithms.conformal_cutoff、conformal_set、betting_path，明确数据用途、秩条件和过程假设；联合失败预算与序贯保证分别表达，任意 betting 曲线不是有效置信保证。

EXT07 复用 BinarySCM/identify_finite：筛与声明观测相容的全部模型，计算干预量、识别集、界及极值见证。独立检查器从结构方程直接算 do 分布与观测分布，不调用 identify_finite。观测等价但因果不同反例、空相容类必须覆盖。精确性仅限完整声明的有限模型类，现实真实性未由程序证明。

EXT07的自由概率权重不离散成网格：有限响应类型配连续单纯形，观测匹配形成约束。线性片段以精确有理LP给可行、对偶及可达极值；潜变量独立等多项式非线性约束直接进入J.0已选全CAD公式，按主文§6构造inf/sup/attainment并保留全部相容模型。条件量的分母正性显式加入定义域。另含exp/log的经验模型仅用主文模量区间给声明精度的界；不能删非线性假设冒充精确线性识别。

### J.6.8 事件与重放

ProcessState按J.4保存实际历史和E，K由独立评价重建。ActualIssued、Effective(effect,target_time,as_of)、LegallyCorrect、Final分别计算；错误但有效的裁判可继续产生执行效力。实际路径使用J_actual；J_legal仅供依法选择的规范模型，只有后者要求支持落在允许集合L。实际裁判、错误付款和违法动作均可记录，结构良构不要求现实行为合法。

step_event 按当前状态与事件检查局部规则，再给状态集合和见证。至少覆盖证据提交/排除/撤回、认定更新、裁判/撤销、履行、程序/救济、规范生效/更替/授权回流。主文必需机制不得是空分支。

新增证据可能缩 K；撤回可能扩 K，应从规范化输入和有效证据重建，不调用 narrow_candidates 硬塞。变更规则/来源使依赖闭包失效，可复用 taint.affected_closure；增量等价未证则完整重算，不能声称一般增量完成。

发生、可见、生效时点分轴。按as_of限定实际前缀，再依具名溯及规则求target_time截面的效果；当时判断不读后来撤销，当前回看保留原付款事实并另生回转义务。为每个程序分别保存阶段，破产中止不把其他争点一并改成终审。

## J.15 六类边界的实际运行与消费合同

理论定义及证明在主文§12.6，Lean落实在I.12，各条独立范围在K.13。以下改动落实在现有求值器、独立checker和唯一持久化通道；不另设一个只保护空系统的“审计服务”。名称均为拟合同，构造和依赖已经选定。

### J.15.1 工作前沿与运行身份

`semanticInputKey`包含规范化全输入、请求、scope、profile、法源/规则内容版本、asOf及精度合同。键相等以这些内容相同为准；仅同案件ID或自称版本不够。`runKey=(semanticInputKey,attemptId)`区分每次运行。`σ=(runKey,T,C,L,W,F)`逐主文构造：T为全部根及其依赖工作树，C为完整核验关闭叶，L为不能关闭域的已核成员/内界，W为未闭叶，F为本attempt追加的技术失败。

- 离散候选用赋值前缀及Q的全部子集；CAD节点用完整投影/根列表/柱；解析节点用已定精度及尾界/区间误差子问题。每个split存父域等于子域之并的具体证书，计数/积分另核互斥。
- 单个连续解仅记L。close须覆盖整个节点目标；只有单候选域时，一个成员/排除判定即可关叶。负结果必须核无解证书，空列表不够。
- 每次serialize保存实际W，`openObligations`从W编码生成，不接收调用方自填“尚待复核”。extend的父目标在全部新增必需子目标关闭前保持打开。
- 资源暂停且无技术失败可以resume同runKey；失败attempt永久保留Failed及已有C/L。修复重跑建立新attempt；相同输入和子问题的旧证书经独立重验后记录新采用事件，不能改旧attempt状态。
- 完整的参考算法具有无预算语义及终止/完备证明；现实预算耗尽只改变该次运行状态。不能靠缩小输入域、删CAD格或截树高度完成。

### J.15.2 独立消费与合法终结

既有CLI、API/MCP、桥接、批量报告、缓存读取和checkpoint恢复的公共载荷消费统一调用拟`acceptRun`。它从当前输入和RawArtifact重建请求、工作树、profile/阶段，运行J.7的独立checker，计算AcceptedRun及法律观察；producer的complete/adverse/PASS字符串没有授权力。解析或证书拒绝保留明确错误原因，不回退默认成功。

规范判断类型的争点q按实际要件、标准、责任、例外和程序终结规则构造Required(q)。被模型认可为合法的不利终结须提交同输入/争点/阶段的法律推导，所有必需求解节点有关闭证书；穷尽或否定前提须全覆盖证据，不能“没搜到支持”即unmet。若另一条独立完整法定依据足以处分，可按该依据接受并公开剩余未完成计算；不因无关争点失败封锁全部案件。checker应接受一个真实法定负担失败的合成实例，不能以拒绝一切满足安全断言。

实际裁判记录使用§9的ActualIssued/Effective类型；ActualIssued路径核发生和来源，权限/形式/生效等法定条件用于另行判断Effective，不要求法律正确。无权、无效或伪造的文书仍可作为具有相应来源标记的实际文书事件记录，不因未满足权限而抹去发生。错误而有效的裁判仍进入实际历史及救济，不被上述LegallyCorrect类型的终结检查拦掉；两种观察不能通过改标签互换。

被动map/bind/allRequired、显示、序列化、缓存装配复用已核分支和runKey，证明逐函数精化到§12.6语法。任何真实必需依赖失败都保留失败轴；被动操作不生成新法律依据。真实完整重跑/独立补证单列主动步骤，仍保留旧失败。

### J.15.3 扩展、保证与实际来源传播

扩展空性按实际profile：complete/stable遍历全部powerset Q，preferred遍历全部admissible再查全部严格超集，grounded有限迭代。独立checker核成员反射/拒绝覆盖，返回树域全扩展的q回拉。自攻点stable空族与grounded/complete/preferred的单元素族{∅}必须不同。

保证向量只对一条推导的实际必需输入逐坐标min；权限凭据库存max只记录已存在最高rank，实际授权仍核主体/用途/范围凭据。不把两者当同构；替代证明按所选依赖单独评价，新独立验证按其健全定理产生ValidatedClaim，不能用重复/投票升格。
